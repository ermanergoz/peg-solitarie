# Phase 3 — UI Design Contract

> Visual and interaction contract for the Challenge-mode UI surfaces. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope: NARROW / DELTAS ONLY.** Phase 3 is primarily a pure-Kotlin domain phase (the deterministic reverse-generation `LevelGenerator` — the project's #1 risk). This contract governs ONLY the three new/changed UI surfaces below. The board rendering (`BoardCanvas`/`BoardMetrics`), jump/removal animation (`GameAnim`, D-07/D-08), the 1–3 star model, and the generic Results layout were locked in Phases 1–2 and are **reused unchanged** — they are referenced here as reuse, never re-specified.

## Surfaces In Scope (new / changed only)

| # | Surface | Change Type | Driving Decision | Reuses |
|---|---------|-------------|------------------|--------|
| S1 | Home → Challenge tile | Enable existing disabled tile; drop "Coming soon"; wire route into Challenge at level 1 | D-04 | `HomeScreen.ChallengeTile`, `surfaceContainerHigh` card, `mode_tile_min_height` |
| S2 | Challenge gameplay top bar | Add a "Level N" indicator | D-03 | Entire `GameScreen` / `BoardCanvas` / `GameViewModel` / timer / hint toggle / restart — unchanged |
| S3 | Challenge-aware Results | Mode/context-aware actions: "Next level" only when solved; "Retry" + "Home" (no "Next level") on stuck; numeric score is level-scaled | D-01, D-10, D-11 | `ResultsScreen` layout, star row, metric block, headline tiers, `results_star_size` |

**Explicitly NOT in scope (reuse verbatim, do not re-spec):** board grid/peg/hole rendering, jump-arc + fade/shrink animation, peg selection highlight, star icon geometry, the SCORE/TIME/PEGS-LEFT metric block layout, the mid-game restart confirm dialog, onboarding, the Classic catalog. Star bands stay the Phase-2 model (D-11 — do NOT re-base stars on speed/efficiency).

## Color

M3 role-based; the stock baseline light/dark schemes are used verbatim (`Color.kt`) — **no hex values in this contract.** The Phase-2 60/30/10 discipline is preserved unchanged.

| Role | M3 token | Usage |
|------|----------|-------|
| Dominant (60%) | `surface` / `background` | Screen background |
| Secondary (30%) | `surfaceContainerHigh` | Mode tiles (S1), board panel, cards |
| Accent (10%) | `primary` | The **single** filled primary Button per Results screen + the filled (earned) stars — nothing else |
| Destructive | not used this phase | No new destructive-colored element introduced |

Accent (`primary`) reserved for — **exhaustive list this phase:**
1. The one filled primary `Button` on the Challenge Results screen — "Next level" when solved (D-01), or "Retry" when stuck (D-10). Exactly one filled accent button per Results state.
2. The earned/filled stars in the reused star row (Phase-2 behavior, unchanged).

Explicitly NOT accent: the "Level N" top-bar indicator (uses `onSurface`, neutral), the Home Challenge tile (stays neutral `surfaceContainerHigh` like the Classic tile — enabling it does not make it accent), and the secondary "Home" action (neutral `OutlinedButton`/`TextButton` with `onSurface` label). The removed "Coming soon" badge was deliberately non-accent and is simply deleted.

| Element | Copy |
|---------|------|

| Primary CTA (stuck) | **Retry** — reloads the same deterministic board (D-10) |

## Interaction Contract (behavioral deltas)

### S1 — Home Challenge tile (D-04)
- Tile becomes **enabled** and tappable; the "Coming soon" pill is removed. Same `surfaceContainerHigh` card footprint and `mode_tile_min_height` as the Classic tile — visually a peer, not a highlighted accent.
- Whole-surface tap navigates into Challenge gameplay at the current `ChallengeProgress` level (level 1 this phase — D-04; in-memory only, no persistence).
- Supporting line: "Endless levels".

### S2 — Challenge gameplay "Level N" indicator (D-03)
- In Challenge mode, the gameplay top-bar **title** shows `Level N` (`titleLarge`, `onSurface`) in place of the static "Peg Solitaire" app-name title. This is the minimal, uncluttered delta — the actions row (timer, hint toggle, restart) is unchanged.
- The indicator carries a `challenge_level_indicator_desc` content description for screen readers.
- Classic gameplay keeps its existing app-name title — the title slot is context-aware, driven by the loaded `LevelRef`/route, with no `if (challenge)` branching leaking into the board/game logic (routing stays in the repository per ARCHITECTURE Anti-Pattern 2).

### S3 — Challenge-aware Results (D-01 / D-10 / D-11)
- Results becomes mode/context aware (planner's choice per CONTEXT: a `mode`/`showNextLevel` flag on `ResultsUiState` vs a parallel Challenge-results route — behavior is fixed here, structure is the planner's call).
- **Solved (1-peg, D-01):** primary filled accent **Next level** button (advances to N+1) + neutral **Home**. (No "Replay" needed — a solve is required to advance and is near-constant 3★.)
- **Stuck (2+ pegs, no legal moves, D-10):** primary filled accent **Retry** button (reloads the same deterministic board) + neutral **Home**. **"Next level" is absent** — the level was not solved.
- Exactly **one** filled `primary` Button per state (accent discipline); the secondary action is a neutral `OutlinedButton`/`TextButton` with an `onSurface` label, matching the Phase-2 Results action styling.
- Headline + star row + metric block are reused unchanged. Stars keep the Phase-2 band model (D-11).
- **Score (D-11):** the SCORE metric shows a **level-scaled** numeric score — a difficulty/level multiplier applied over the pure Phase-2 `ScoreCalculator` base, passed in as a pure parameter (no coupling of `ScoreCalculator` to level state). Stars are NOT re-based; only the numeric score scales. Rendering of the metric is otherwise identical to Phase 2.
