<objective>
Build the Results destination — the payoff screen (D-05, replacing the Phase-1 `GameOverDialog`) — as the locked Route → Screen → ViewModel → UiState quadruple. It surfaces the numeric score, stars, pegs remaining and elapsed time (SCOR-03), tiers the headline to the star outcome (D-08), and offers the four actions with a wrapping "Next board" (D-06).

Purpose: SCOR-03 requires a results screen that shows stars + pegs + time + score; SCOR-01/SCOR-02 values are computed by the pure-domain `ScoreCalculator` (02-01) and arrive as typed `Results` route args (never recomputed in the composable). The "Next board" wrap reads the catalog order from `LevelRepository` (02-04). This closes the gameplay→results half of the spine started in 02-05.

Output: `ui/results/{ResultsRoute,ResultsScreen,ResultsViewModel,ResultsUiState}.kt` + `ResultsViewModelTest.kt`.

Phase Goal (MVP): As a casual puzzle player, I want to play any of five classic boards from a Home/catalog flow and see stars and a score at the end, so that finishing a board feels rewarding. This plan delivers the "see stars and a score" payoff.
