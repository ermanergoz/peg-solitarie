| terminal status → Results route args | `stars/pegsRemaining/elapsedSeconds/score` are emitted into a navigation arg consumed by Results. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-05-ID | Tampering / DoS | GameViewModel.loadClassic(levelId) | mitigate | The repository (02-04) validates the id against the named-constant `ClassicLevelIds` catalog and fails fast; the Gameplay route is only ever constructed from a catalog-emitted id (02-07). The VM does not catch — a forged id fails loudly in tests, never silently loads a wrong board. |
| T-02-05-ARG | Tampering | Results route args (stars/pegs/elapsed/score) | mitigate | The args are computed in-VM from the validated `Board.pegCount` and the monotonic in-VM timer, then passed by the typed `@Serializable` route; `stars` is `ScoreCalculator`-clamped to 1–3 and the time term is floored at 0 (02-01), so out-of-range values cannot be injected by the navigation layer. Results re-derives nothing trust-sensitive (display only). |
| T-02-05-NAV | Tampering | terminal→Results re-navigation | mitigate | The finish event is a one-shot Channel + `finishedEmitted` guard (Pitfall 4); GameRoute collects it inside a `LaunchedEffect`, so a recomposition cannot re-fire Results or pollute the back stack. |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan (deps added in 02-03; Maven ecosystem — slopcheck N/A). |
</threat_model>
