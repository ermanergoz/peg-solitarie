# Phase 4 — UI Design Contract

> Visual and interaction contract for the Assist (Hint & Undo) phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This is a native **Android / Jetpack Compose + Material 3** project, not a web/React app. The shadcn initialization gate is **not applicable** (shadcn is a React/Next/Vite tool). The "design system" here is the established M3 baseline theme + scoped resource tokens (`dimens.xml`, `BoardMetrics`, `GameAnim`, `strings.xml`) already shipped in Phases 1–3. This spec **extends** those tokens for the three new Phase-4 surfaces; it does not re-specify what already exists.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Android; shadcn N/A) |
| Preset | not applicable |
| Component library | Material 3 (Compose BOM 2026.06.00) — M3 baseline, dynamic color / bespoke theming deferred to Slice 2 (POLI-01) |
| Icon library | `androidx.compose.material:material-icons-core` — **core set only** (extended set intentionally avoided; established Phase-2 constraint) |
| Font | Platform default (Roboto) via M3 stock `Typography()` — custom fonts are Slice 2 (POLI-01) |

**Governing rule (CLAUDE.md QUAL-03):** no color reaches a composable except through `MaterialTheme.colorScheme.*` roles; no fixed dp/sp reaches a composable except through `dimensionResource(...)`; proportional board geometry lives as unitless ratios in `BoardMetrics`; durations/easings in `GameAnim`; all copy in `strings.xml`. The custom `dpSpLiteralCheck` gate + `DomainPurityTest` fail the build on a violation.

## Spacing Scale

Declared in `app/src/main/res/values/dimens.xml` (8-point grid, all multiples of 4). **Reuse these — do not introduce new spacing tokens for Phase 4.**

| Token | Value | Usage |
|-------|-------|-------|
| `spacing_xs` | 4px | Icon gaps, inline padding |
| `spacing_sm` | 8px | Compact spacing (banner action-row gaps, timer trailing pad) |
| `spacing_md` | 16px | Default element spacing (rescue-banner content padding, board margin) |
| `spacing_lg` | 24px | Section padding / dialog padding |
| `spacing_xl` | 32px | Layout gaps |

Phase-4-relevant fixed tokens (reused, not new): `top_bar_icon_size` = 24dp (Hint/Undo icons + the thinking spinner), `board_min_touch_target` = 48dp (each new icon button meets this via the default `IconButton` 48dp hit box), `board_max_size` = 480dp (board panel cap the banner sits under).

**Exceptions:** stroke widths `peg_selected_ring_width` (3dp) and `hole_outline_width` (1dp) are the pre-existing intentional sub-4dp rendering exception (a 4dp ring overpowers the small peg geometry). Phase 4 adds **no new dp exceptions** — the hint ring/arrow are proportional `BoardMetrics` ratios, not dp.

**New for Phase 4 — one dimen token permitted:** `nowin_banner_min_height` = 48dp (multiple of 4) for the inline rescue banner's minimum height so its three actions stay tap-reachable. All other banner spacing reuses `spacing_md`/`spacing_sm`.

## Typography

Material 3 stock `Typography()` on Roboto — **exactly two weights** (Regular 400 + Medium 500), every role maps to sp internally. Composables reference `MaterialTheme.typography.*`; never a raw `sp` literal. Phase 4 introduces **no new type roles** — it reuses the roles already in play.

| Role | M3 token | Size | Weight | Line Height | Phase-4 usage |
|------|----------|------|--------|-------------|---------------|
| Body | `bodyMedium` | 14sp | Regular 400 | 20sp (1.43) | Rescue-banner message text |
| Label | `labelLarge` | 14sp | Medium 500 | 20sp (1.43) | Rescue-banner action buttons (Undo · Restart · Home) |
| Title (secondary) | `titleMedium` | 16sp | Medium 500 | 24sp (1.50) | (existing timer — unchanged) |
| Title (primary) | `titleLarge` | 22sp | Regular 400 | 28sp (1.27) | (existing top-bar title — unchanged) |
| Heading | `headlineSmall` | 24sp | Regular 400 | 32sp (1.33) | (existing dialog title — unchanged) |

Body line-height 1.43 and heading line-height 1.33 are the M3 baseline and are accepted as-is (within the ≥1.2 heading / ~1.5 body targets). Icon-only controls (Hint, Undo, Show-possible-moves toggle) carry **no visible text** — their meaning is conveyed by icon + tint + a `contentDescription` string (accessibility parity with the existing `RestartControl`).

## Color

M3 baseline roles only (zero hex in code). The board palette is captured from `MaterialTheme.colorScheme` into `BoardPalette` and handed to the `DrawScope`. Phase 4 adds **one new accent role** (`tertiary`) to keep the winning-move Hint visually distinct from ordinary selection (`primary`).

| Role | M3 token | Usage |
|------|----------|-------|
| Dominant (60%) | `surface` / `background` | Screen background behind the board panel |
| Secondary (30%) | `surfaceContainerHigh` (board panel), `secondary` (pegs) | The board panel surface and the peg fill |
| Accent — selection (10%) | `primary` | **Existing, unchanged:** selected-peg ring, legal-destination dots, Show-possible-moves toggle ON tint, dialog confirm button |
| Accent — hint (new, ≤10%) | `tertiary` | **Phase 4 only:** winning-move Hint highlight — source-peg glow ring (A), target-hole ring (B), and the faint A→B arrow |
| Problem surface | `errorContainer` / `onErrorContainer` | The inline no-win / stuck **rescue banner** background + text (soft M3-tinted, non-alarming) |

**Accent reserved-for list (explicit — never "all interactive elements"):**
- `primary` → peg selection ring, legal-destination dots, the persisted "Show possible moves" toggle when ON, and dialog confirm text.
- `tertiary` → the on-demand winning-move Hint highlight (source glow + target ring + arrow) **only**. Using a second accent role is deliberate: it makes "a hint is being shown" unmistakably different from "I selected this peg" (`primary`), satisfying D-01/D-02's disambiguation intent at the color layer.

**Destructive:** No genuinely destructive action is introduced this phase. Undo is non-destructive (rewinds board + history, timer untouched per D-07). "Restart" (offered in the rescue banner) discards progress but is already governed by the existing mid-game confirm dialog (D-06 pattern) and does not need the `error` role. The `error`/`errorContainer` role is used here only as the **problem-state surface** for the no-win/stuck banner, not for a destructive-button treatment.

## Copywriting Contract

All copy lives in `strings.xml`. New Phase-4 strings below; the D-02 rename repoints the existing toggle strings.

| Element | Copy | String key (proposed) |
|---------|------|------------------------|
| **Primary CTA (this phase)** | "Hint" (icon-only control; this is the `contentDescription`) | `hint_action` |
| Hint — thinking state | "Finding a move" (announced while the Solver runs; button disabled, D-10) | `hint_thinking` |
| Undo control | "Undo" (icon-only `contentDescription`) | `undo_action` |
| Renamed dots toggle — ON (D-02) | "Show possible moves" | `show_moves_on` (replaces `hints_on`) |
| Renamed dots toggle — OFF (D-02) | "Hide possible moves" | `show_moves_off` (replaces `hints_off`) |
| **No-win rescue message (verbatim, D-08)** | "No winning move — undo or restart" | `nowin_message` |
| Stuck rescue message (D-06, parallel phrasing) | "No moves left — undo or restart" | `stuck_message` |
| Rescue banner action 1 | "Undo" | reuse `undo_action` |
| Rescue banner action 2 | "Restart" | `rescue_restart` (label form; distinct from the `restart_board` content-desc) |
| Rescue banner action 3 | "Home" | reuse `action_home` ("Home") |

**Empty state (this phase's analog):** there is no data-list surface in Phase 4. The nearest "there is nothing to act on" state is the **rescue banner** — surfaced when the position has no winning continuation (no-win) or no legal move at all (stuck). Copy above; the banner always presents a next step (Undo · Restart · Home) so the player is never dead-ended.

**Error state (problem + solution path):** the no-win banner is the error surface. Problem = "No winning move"; solution path = "— undo or restart", with Undo · Restart · Home actions rendered on the still-interactive board (non-blocking, not a modal — D-08). Budget-miss is folded into this same state (D-04): a Solver that fails within budget surfaces "No winning move", never a crash or silent no-op (ASST-03).

**Destructive confirmation:** "Restart" from the rescue banner reloads the same deterministic board and discards current progress — route it through the **existing** `RestartConfirmDialog` (D-06): title "Restart this board?", body "Your current progress will be lost.", confirm "Restart Board", dismiss "Keep Playing" (`restart_confirm_title` / `restart_confirm_body` / `restart_board` / `keep_playing`, all already in `strings.xml`). Undo requires no confirmation. "Home" exits to the Home root (existing back-nav target).

## Interaction Contract — New Surfaces (Phase 4)

Prescriptive contract for the three new UI elements. All are **stateless leaves** with hoisted state/handlers (compose-skill), mirroring `RestartControl`/`HintToggleControl`.

### 1. Hint control (`HintControl.kt`) — the winning-move action (D-01/D-10)
- Top-bar `IconButton`, icon sized `top_bar_icon_size` (24dp), core-set glyph (recommend `Icons.Rounded.Search` — "find the winning move"; must be from `material-icons-core`). `contentDescription` = `hint_action` ("Hint").
- **Thinking state (D-10):** while `solverThinking`, replace the icon with a `CircularProgressIndicator` sized `top_bar_icon_size` and **disable** the button (prevents double-taps); `contentDescription` switches to `hint_thinking` ("Finding a move"). Usually sub-second — a brief flash is acceptable.
- **On result:** the ViewModel writes the highlight fields (below) or the no-win flag; the control returns to its resting icon. **Never auto-performs the jump** (D-01) — highlight only.
- Tint: resting `onSurface` (neutral, like `RestartControl`); it is an action, not a persisted toggle, so it does **not** use the `primary` ON/OFF tint pattern.

### 2. Undo control (`UndoControl.kt`) — multi-step rewind (D-05/D-07)
- Top-bar `IconButton`, icon `top_bar_icon_size`, core-set glyph `Icons.AutoMirrored.Rounded.Undo`. `contentDescription` = `undo_action` ("Undo").
- **Disabled** (no-op, reduced tint `onSurfaceVariant`) when `moveHistory` is empty; enabled `onSurface` otherwise. Repeated taps walk back to the initial board (D-05). No redo.
- Undo clears any active hint highlight and no-win/stuck banner, leaves the timer untouched (D-07).

### 3. Winning-move highlight on `BoardCanvas` (D-01)
Extend `DrawScope.drawBoard`/`drawCell`. New `GameUiState` fields (all `val`, `@Immutable`): `hintSource: Position?`, `hintTarget: Position?`. New `tertiary` color captured into `BoardPalette`. New proportional ratios in `BoardMetrics` (unitless × cellSize — **not** dp):

| New `BoardMetrics` ratio | Value | Meaning |
|--------------------------|-------|---------|
| `HINT_SOURCE_RING_RATIO` | 0.42f | Glow ring radius around the peg to move (A) — slightly > `SELECTED_RING_RATIO` 0.40 so hint ≠ selection |
| `HINT_TARGET_RING_RATIO` | 0.30f | Ring radius around the destination hole (B) — > `DESTINATION_DOT_RATIO` 0.18 so it reads as a target, not a dot |
| `HINT_ARROW_WIDTH_RATIO` | 0.06f | Stroke width of the faint A→B arrow as a fraction of cellSize |
| `HINT_HIGHLIGHT_ALPHA` | 0.9f | Alpha of the `tertiary` source/target rings |
| `HINT_ARROW_ALPHA` | 0.5f | Alpha of the "faint" A→B arrow (D-01 says *faint*) |

Draw order: target ring (B) → source glow ring (A) → arrow `Path` from `geometry.center(source)` to `geometry.center(target)`, all in `tertiary`. Highlight is suppressed in the read-only catalog preview (`interactive = false`), like selection/dots today.

### 4. Rescue banner (`NoWinBanner.kt`) — shared no-win + stuck surface (D-06/D-08/D-09)
- **One shared component**, parameterized by message string (research Open-Q 2): `nowin_message` for Solver-confirmed-no-win/budget-miss, `stuck_message` for a stuck board.
- Inline, **non-blocking** M3 `Surface` (NOT an `AlertDialog`), color `errorContainer`, text `onErrorContainer` `bodyMedium`, corner radius `MaterialTheme.shapes.medium`, content padding `spacing_md`, min height `nowin_banner_min_height` (48dp). Positioned over/under the still-visible, **still-interactive** board so the player can act immediately (D-08).
- Three `TextButton` actions in a row (`spacing_sm` gaps), `labelLarge`: **Undo · Restart · Home** (D-09). Undo → `onUndo`; Restart → the existing `RestartConfirmDialog` then reset; Home → Home root.
- Shown when the ViewModel sets the rescue flag; **Won never shows the banner** (Won → Results as before). Cleared on Undo-into-Playing or Restart.

### 5. D-02 rename (strings only)
Repoint `HintToggleControl` from `hints_on`/`hints_off` to `show_moves_on`/`show_moves_off`. The toggle stays a pure render gate for legal-destination dots (`primary` tint when ON). Icon (`Icons.Rounded.Info`) unchanged. The new winning-move "Hint" is the separate `HintControl` above — the two are now unmistakably different.

## Animation & Motion

Reuse `GameAnim` tokens (ms + easings; scoped object, not dp/sp). Phase 4 adds **no new motion timing** — the functional highlight ships now; richer arrow-animation polish is explicitly deferred to Slice 2 (POLI-01, per CONTEXT Deferred). The hint highlight may reuse `SELECT_FADE_MS` (120ms, `SELECT_FADE_EASING`) for its fade-in to match the existing selection affordance. The thinking spinner uses the M3 `CircularProgressIndicator` default indeterminate motion.
