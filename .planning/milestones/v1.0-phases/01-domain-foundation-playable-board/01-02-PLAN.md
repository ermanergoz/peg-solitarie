## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | `RulesEngine.applyMove` receiving a forged/illegal `Move` | accept (gated upstream) | `RulesEngine` is the single source of legal moves via `legalMoves`; the caller (Plan 03 `GameViewModel`) only ever applies a `Move` that is a member of `legalMoves(board)` (see T-03-01). `applyMove` itself is a pure transform and is deliberately not a re-validation point — re-validating here would duplicate authority. The domain never crashes: out-of-spec positions resolve to `Blocked`/no-op via `cellAt`. |
| T-02-02 | Tampering | Mutated `Board` re-used as if unchanged | mitigate | All models immutable `data class` with `val`; every move returns a new `Board` via `copy()`; `BoardTest` asserts a board after add/remove of the same peg equals the original (no in-place mutation, Pitfall 6). |

**Honest assessment:** Pure in-memory logic, no I/O, no network, no untrusted external input at this layer (taps arrive only in the UI plans). No high-severity threats. The only meaningful control is keeping `RulesEngine` the sole move authority and the model immutable — both enforced by tests.
</threat_model>
