### 1. The glyph gap: what is true, why the earlier check lied, and the mechanism

**Facts, re-verified here, not taken on trust.** `shasum -a 256` of the shipped `fredoka_medium.ttf` and `fredoka_semibold.ttf` equals D1's (`8143bd54…`, `021e30b2…`): the files are the unmodified Google Fonts v17 static instances, not subsets. `hb-shape --no-glyph-names --no-positions --no-clusters <face> 'ĞğİŞşıÇç—…’·×'` on 2026-11-01: both Fredoka files give 18 glyphs for 13 characters — `20|308`, `81|308`, `22|302`, `46|312`, `108|312` for Ğ ğ İ Ş ş (base + breve 308, dot above 302, cedilla 312), then single glyphs for ı Ç ç — … ’ · × — and no gid 0; the three Nunito files give 13 single glyphs. That is exactly the September `.notdef` check reproducing its false pass. The developer's cmap read (fontTools 4.68.0; `java.awt.Font.canDisplay` in `BundledFontGlyphCoverageTest`, red when pointed at Fredoka: "[U+011E Ğ, U+011F ğ, U+0130 İ, U+015E Ş, U+015F ş]") is the one that predicts a device, because Minikin picks the font per code point from cmap coverage before HarfBuzz ever runs. Recorded in §11.1 and §17; **retro candidate (tech-lead, own error):** a font-coverage claim is proven by a cmap read, never by a shaper, family metadata or a file size.

**D-16's mechanism (ux-designer's rules 1–5 in spec §7.3, each met):**
- *Rule 1, the same locale resolution as the strings:* **M-1**, `R.bool.display_face_covers_language` in `values/` (true) and `values-tr/` (false), read by `booleanResource` in `AppTheme`. Per-app language and a mid-game switch both recreate `MainActivity` (no `configChanges`), and the new composition reads the bool under the new configuration; no language tag is compared in code (tr-CY rides along; a later locale is one line).
- *Rule 2, the fixed surfaces by a named style:* **M-3**, `BrandTypography(wordmark, clock, pillValue, statValue)` built from `AppTypography` only, provided by `LocalBrandTypography` with a Fredoka default, the five call sites retargeted: `HomeHero.kt:99`, `TimerDigits.kt:122`, `GameStatusStrip.kt:263`, `HomeProgressRibbon.kt:342`, `ResultsScreen.kt:380`. `TimerDigits` measures the style it is handed, so 18d's cells and every measured width hold.
- *Rule 3, English untouched:* **M-2** builds `AppTypography` from the same parameterised `clayTypography` with `(AppFonts.Fredoka, Medium, SemiBold)`, byte for byte as today; T1 and T2 are unchanged; the `en-rUS` case of the typography test is the guard.
- *Rule 4, the two §7.6 tests:* **M-5.1** the two-language typography test (every heading role Nunito at the D-16 weight under `tr-rTR`, body/label and every size, line height and tracking equal to `AppTypography`'s, the four brand styles Fredoka; everything equal to `AppTypography` under `en-rUS`; the pure `typographyFor` cases); **M-5.2** a `tr-rTR` rendering case against the Nunito oracles already in `TypeScaleFixture`; **M-5.3** `BundledFontGlyphCoverageTest` extended: the Fredoka faces against the closed set ("Peg Solitaire"'s letters, 0–9, ":", "/", "—") and the untranslatable values those surfaces draw, each asserted `translatable="false"`; target shape (built now if it costs no more, else §14.3 item 14): every shipped locale × every role's resolved file, derived from the folders and `resources.getResourceEntryName`, never typed, plus "`res/font/` is the only `font*` directory".
- *Rule 5, a later locale:* M-1's bool and M-5.3's derivation make it one resource line and a red test, never a device discovery.
- **Why not `res/font-tr/` (M-4):** `AndroidFontLoader` does load `ResourceFont`s through `ResourcesCompat.getFont` (ui-text 1.11.3, `AndroidFontLoader.android.kt:66`), so qualifiers would resolve; but `createFontFamilyResolver(context)` uses the process-global `GlobalTypefaceRequestCache` (`FontFamilyResolver.android.kt:75`), keyed by `TypefaceRequest(fontFamily, fontWeight, fontStyle, fontSynthesis, resourceLoaderCacheKey)` with `AndroidFontLoader.cacheKey = null` (`:62`). Same family object, same `R.font` id, same key in both languages: after a switch the old typeface is served until process death. Rejected without a test; the test that would show it is written down in §11.1 for anyone who insists.
- **15e:** none owed as built at `f289546` (no first-frame code changed; the resource table only shrank). M-2/M-3 change `AppTheme` and `HomeHero.kt`, first-frame code in start-path directories, so **one sitting on `Pixel_9a_bench`** with the final code, arm A its merge-base at the sitting. The bench measures the English first frame; the Turkish one loads no more faces and is QA's.
