## Findings

1. **Medium — `app/src/test/java/com/app/pegsolitaire/ui/UserFacingTextHasNoProtectedNamesTest.kt:36` adds a compiler warning the gate forbids growing.** The added line `assertThat(stringFiles.map { it.parentFile.name }).contains(TURKISH_VALUES_DIR)` calls `.name` on `File.parentFile`, which the toolchain types `File?`; `compileDebugUnitTestKotlin --rerun` prints `36:38 Only safe (?.) or non-null asserted (!!.) calls are allowed on a nullable receiver of type 'File?'`. The base file at 37d3052 has no such call, so the warning is this diff's. Tech-design §9.8 ("While it holds, no growth"): a diff that adds a unit-test compilation warning in a file it touches is a review finding, fixed in that diff; the recorded exception covers only the `createComposeRule` deprecation. The developer's report claims "3 new `w:` lines, all the v1 `createComposeRule` deprecation … None from the other new files" — the claim misses this touched (not new) file. Failure scenario: when §9.8's held deviation closes and `allWarningsAsErrors` reaches `:app`'s unit-test compilations (before the first `release/*` after 3.0.0), this line turns the Check red; until then it is growth the ruling says is fixed in the diff that adds it. Fix in the diff, developer's choice (one line; `parentFile?.name`, or map the listed directories' names before turning them into files); `!!` is not the fix (rules/kotlin-android.md).

2. **Low — `app/src/test/java/com/app/pegsolitaire/locale/AppLanguagesTest.kt:100-106`: the expected locale list treats every `values-<x>/strings.xml` as a language.** `languagesWithStrings()` keeps any directory whose name starts with `values-` and holds a `strings.xml`, then strips the prefix. Today only `values-tr` qualifies, so the test is right; but `values-night`, `values-v35` and `values-night-v35` already exist beside it. Failure scenario: a later branch adds a `values-night/strings.xml` (a theme-specific string) or a `values-v35/strings.xml`; `theLocaleListNamesTheBaseLanguageAndEveryLanguageWithStrings` then demands `night` or `v35` in `locales_config.xml`, a locale that does not exist, and the only ways out are a bogus `<locale>` entry or editing the test. Non-blocking: no such file exists, the failure is loud and names its cause, and the fix (filter to language-shaped qualifiers, or read the folders' configuration through AAPT) belongs to whoever adds such a file, or to this branch's developer if the fix round for finding 1 is open anyway.

3. **APPROVED SUPPRESSION-EQUIVALENT (nothing suppressed): `app/src/main/AndroidManifest.xml:34` — `[UnusedAttribute]` on `android:localeConfig="@xml/locales_config"`, approved by code-auditor.** Decision on the developer's open item: **accept the warning as it stands; no `tools:targetApi`, no `tools:ignore`, no switch to AGP's `generateLocaleConfig`.** Reasons: (a) the warning is a true statement of intended behaviour — the attribute exists from API 33 and the spec's D-9 wants exactly that (Android 12 and below follow the system language), with `minSdk = 24` in `build-logic/src/main/kotlin/android-app.gradle.kts:30`; there is nothing wrong to fix. (b) Android Lint keeps warnings as warnings for 3.0.0 (tech-design §9.8 ruling 2), so the Check is green and the line stays visible in `lint-results-debug.txt`, where this approval covers it. (c) `tools:targetApi="33"` or `tools:ignore="UnusedAttribute"` on `<application>` silences ApiDetector for every attribute of that element (and, for `targetApi`, its subtree) — wider than the warning, and precisely the "hide rather than fix" §9.8 refuses; a `lint.xml` ignore would be the baseline the studio forbids. (d) AGP's `generateLocaleConfig` injects the same attribute into the merged manifest: it changes who writes the attribute and removes the hand-kept list, not what the attribute does; choosing a mechanism to dodge a lint line is a worse reason than the line, and the hand-written `res/xml/locales_config.xml` is explicit, reviewable, and held to the resource folders by `AppLanguagesTest` (the spec §7.4 allows either; the tech-lead signs off the choice, §9.2). Condition: this acceptance is for 3.0.0; when §9.8's deviation closes with `warningsAsErrors` in lint, the branch that closes it re-rules this line with its auditor, naming the narrowest declaration then available. Record line for the PR text: `approved by code-auditor: AndroidManifest.xml:34 [UnusedAttribute] android:localeConfig — API-33-only by design (spec D-9), lint warnings held for 3.0.0 (tech-design §9.8), nothing silenced`.
