## Architecture
- **`audio/` owns playback.** `SoundPoolPlayer` is still the only `SoundPool`; the two new readers (`AndroidSystemAudioState`, `ProcessAppVisibility`) and the pure pieces live in `audio/`, not `platform/`, for the reason `di/AudioModule.kt` records. `SoundPlayer` and every caller are unchanged; no `UiState` carries a mute.
- **Main thread.** Platform reads run in the collectors on the application scope's `Dispatchers.Default` (`di/DataModule.kt:99`); the listeners only `trySend`; `play()` gains two volatile reads and no IPC (`SoundPoolPlayer.kt:220`). `AudioManager` is fetched lazily, so `App.onCreate` does no new IPC.
- **Haptics** are a UI concern in `ui/game/` (not `audio/`, per Ruling 1), gated by `hapticsOn` and the API floor only; never by Sound, the ringer or the background gate (`WrongTap.kt:95-98`, `JumpHapticEffect.kt`).
- **No Android in `:domain`.** No file under `domain/` changed; `WrongTapKind`, `WrongTapRedirect` and `WrongTapMotion` are `:app` UI types.
- **Hilt.** Three `@Binds` (`AudioModule.kt:45,54`, `DataModule.kt:64`); the interface-to-supertype binding compiles, and the Check's green Hilt build is its proof. Constructor injection only; no `GlobalScope`; the new `TutorialViewModel` collector is on `viewModelScope`.
- **Compose and draw phase.** Per-frame values are read in draw through `clock.value` and `timing.value` (`WrongTapFeedback.kt:200-222`), so a shake or nudge redraws without recomposing; `Offset` is a value class and the keyframe lookup is index-based, so `drawCell` allocates nothing per frame; the dashed `Stroke` is built once in composition. `BoardCanvas` recomposes once per wrong tap and once per `dotRePops`/`announcement` change — bounded and acceptable. UDF holds: the ViewModels write the signal, the canvas only reads it, and ending an answer never writes state.
- **Security.** No network, no new permission, no secret; the receiver is `RECEIVER_NOT_EXPORTED`; only `AudioDeviceInfo.getType()` is read. No new dependency, so THIRD_PARTY.md needs no row.
