## 1. Diagnoses and mechanism rulings
### 1.1 D-03n's heights — a measure policy over the band column (pre-ruled)
§4.2.5 leaves the mechanism to the developer and routes anything beyond layout to me. I rule it now, so no round trip is needed: **the mechanism is layout, in one of two shapes, both accepted.**

Why the weighted `Column` cannot do it: `HomeScreen.kt:383-448` hands the slack to two weights (`STAGE_WEIGHT = 3f`, `SLACK_BELOW_TILES_WEIGHT = 1f`) over `heightIn(min = availableHeight)`. A weight is a share of the *current* slack, and D-03n's footer is a share of the *no-chip* slack, fixed for the window. No weight pair expresses "the footer holds still while the chips take their room from the stage".

**The quantities, in the Layout's measure pass** (every term in px; `gap` = the band spacing the set chose, `pad` = the column padding, already outside the Layout):
- measure the hero, the ribbon, both tiles, and each chip present, at the column's width, unbounded height;
- `S₀ = max(0, inner − hero − ribbon − tile1 − tile2 − 5·gap)` where `inner = availableHeight − 2·pad`, `availableHeight` the `BoxWithConstraints` `maxHeight` the Layout is handed as a parameter (inside `verticalScroll` its own max height is infinite);
- `R = Σ over chips present of (chip_i + gap) · f_i`, `f_i` the chip's room fraction (1 when settled, §1.2);
- `footer = min(S₀/5, max(0, S₀ − R))`, `stage = max(0, ⅘·S₀ − R)`;
- height reported = `hero + gap + stage + gap + ribbon + gap + R + tile1 + gap + tile2 + gap + footer`, which equals `inner` while `R ≤ S₀` and overflows by `R − S₀` after, so the column scrolls as §4.2.2 requires (criteria 14, 15i, 15k's total height is unchanged per chip state);
- place top-down in band order; tile 1's top is then `pad + hero + ribbon + 3·gap + ⅘·S₀`, independent of `R` wherever `R ≤ ⅘·S₀` — which is criterion 15s's part 1 by construction, and 15t's shortfall `max(0, R − ⅘·S₀)` after it.

The ratio is one constant, `FOOTER_SHARE_OF_SLACK = 0.2f` (name is the developer's; unitless, in the home package's scoped constants, with a KDoc pointing to §4.2.5's three reasons). `STAGE_WEIGHT` and `SLACK_BELOW_TILES_WEIGHT` are deleted, not kept (§4.2.4's pointer: not to be rebuilt). `BoxWithConstraints`, `verticalScroll`, `widthIn(max = content_max_width)`, `padding(bandSpacing)`, `align(TopCenter)` and `homeBandSetFor` stay exactly as they are; `heightIn(min)` goes, because the Layout now reports the height.

**Two accepted shapes** for how the stage learns its *settled* height, which §1.3's fade needs and only the measure pass knows (S₀ depends on text wrapping):
- **(a) `SubcomposeLayout`** for the band column: subcompose and measure the fixed bands and the chips first, compute the numbers, then subcompose the stage slot with `(height, width, artFade)` as parameters. Exact in the same frame. This is the pattern `BoxWithConstraints` already is, so its cost class is the one Home's first frame already pays twice (`HomeBands`, `HomeStage`); the stage slot recomposes on each frame of a 240 ms transition, which is a Box and one Canvas.
- **(b) a plain `Layout`** whose measure pass writes the settled-stage verdict into a `MutableState` **only when it changes** (`if (state.value != computed) state.value = computed`), read by `HomeStage` in composition. One frame late at a transition's start, invisible in a 15-frame fade; zero writes in steady state.
Rejected: `onSizeChanged`/`onGloballyPositioned` feeding a state that recomposes the stage (that is part 4's own defect pattern, §1.4); a `LaunchedEffect` after layout; estimating S₀ from text measured in composition (layout metrics differ). Pick (a) or (b), say which in the report; the code-auditor reads it against this subsection.

### 1.2 The motion, and the late chip's zero stagger
- One `Animatable<Float>` room fraction per chip slot, owned by `HomeBands`: initial value 1f for a chip present at Home's first composition, 0f otherwise; `LaunchedEffect(chipPresent)` animates to the target with `tween(ClayAnim.ENTRANCE_MS, easing = ClayAnim.ENTRANCE_EASING)` (no overshoot), or `snapTo` when `rememberAnimationsEnabled()` is false (15u's last sentence; §10's reduced-motion bullet).
- The chip slot: the chip measured at its natural height, the slot reporting `height · f` and clipping (`Modifier.clipToBounds()` ahead of a `Modifier.layout { }` that places the chip at the top), so the room grows from the ribbon's edge and nothing overlaps while it opens. The Layout adds `gap · f`, so no gap shows ahead of its chip (15u).
- A chip **leaving** stays composed while `f > 0`: latch its last data (`classicResumeLevelId`/`classicResumeBoard`, `challengeResumeLevel`) in a `remember` so the closing room still shows the chip it was; both → none in 15u reads it.
- **A chip that arrives after first paint takes no stagger** (§4.2.5 "The motion", F-14): `remember` at `HomeBands`' first composition which chips were present; a chip absent then and present later is composed with `clayEntrance(0)`, so its fade starts in the frame its room starts opening. Nothing in `Clay.kt` changes for this; the tiles' entrance already ran, so their counted orders stay as they are.
- The cascade (`clayEntrance`) is a `graphicsLayer` offset and never a layout move (§4.2.5 F-22); the Layout places bands by layout position, so the two are independent and the cascade is never restarted (15v part 3).

### 1.3 The stage art at the end of its range (§4.2.5 F-25)
`HomeStage.kt:76-80` composes the art only when `edge ≥ home_stage_art_min_size`. Under a transition whose settled edge is below the minimum, the art is kept composed while `f < 1`, shrinks with the stage, and fades over the same `ENTRANCE_MS` (`graphicsLayer { alpha = 1 − f }`, multiplied with `clayEntrance`'s own alpha); it is gone when the room has opened. ### 1.4 Part 4 — why the slab draws ≈ 0.26 s before its pegs, and the drawing-only fix
**Diagnosis (read, not run).** `BoardCanvas.kt:95-96` builds the geometry from a size held in state: `var canvasSize by remember { mutableStateOf(Size.Zero) }` and `remember(spec, canvasSize) { BoardGeometry.forCanvas(spec, canvasSize) }`. That state is filled by `.onSizeChanged { canvasSize = it.toSize() }` (`:201`) during the **first layout**, after the first composition. The first frame's draw lambda therefore reads a not-ready geometry, and `drawBoard` returns at once (`if (!geometry.isReady) return`, `:382`). The slab (`HomeStageArt`'s `background`) and the tile `Card` are painted by their own modifiers in frame 1; the pegs arrive with the recomposition the state write schedules — frame 2, which on a cold start is ≈ 0.26 s later because the font loads, the ribbon's emission and the chips' decode all sit between the two frames. The same holds for every `StaticBoardArt` (the Classic tile, the Continue thumbnail) and the catalogue previews. This is a drawing matter, so it is the developer's; no further ruling is owed.

**The fix.** In the `Canvas` lambda (`:214-220`), draw with a geometry of the frame's own size: `val frameGeometry = if (canvasSize == size) geometry else BoardGeometry.forCanvas(spec, size)`, and pass `frameGeometry` to `drawBoard`. `canvasSize` is the size the composition-held geometry was built from, so equality means it matches this frame; the allocation happens only on a frame whose size the state has not caught up with (frame 1, and each frame of a stage resize), and never in steady state (rules/compose.md, no allocation in hot draw). The composition-held `geometry` keeps serving `pointerInput(geometry)` and the jump `LaunchedEffect` unchanged, so the tap and animation paths are byte-identical, and the read-only path composes nothing new. During the stage's 240 ms resize this also keeps the pegs on the slab in every frame (§10: "the pegs on it do not move relative to the board"), which the stale-by-one-frame geometry would not. `BoardGeometry.kt` needs no change. Under `clayEntrance(HERO_ENTRANCE_ORDER)` the slab and its pegs now fade together at one alpha (15v part 4).

**Its test, `BoardCanvasFirstFrameTest`** (`ui/components/`, Robolectric NATIVE, `AppTheme`): with `mainClock.autoAdvance = false`, compose `StaticBoardArt(Boards.english33Initial)` at `home_tile_art_size`; advance exactly one frame; read the window (`renderedWindow()`) inside the canvas's bounds and assert peg ink is present and that the frame-1 pixel set equals the settled frame's (then `autoAdvance = true`, `waitForIdle()`); a second case on `HomeStage` at `w411dp-h915dp` with insets.
