A **list**, never a pair. The catalogue types, all in `ui/licenses/LicenseCatalog.kt`:

### 1.2 The pure merge — `GoogleNoticeMerge`
```kotlin
class AarNotices(val artifactId: String, val json: ByteArray?, val txt: ByteArray?)
data class NoticeIndexLine(val key: String, val name: String, val stem: String, val sources: List<String>)
class MergedNotices(val lines: List<NoticeIndexLine>, val texts: Map<String, ByteArray>) { fun indexTsv(): ByteArray }
class GoogleNoticeMergeException(val artifactId: String, reason: String) : RuntimeException("$artifactId: $reason")
object GoogleNoticeMerge { fun merge(aars: List<AarNotices>): MergedNotices }
```
- **Per AAR:** `json == null` → contributes nothing (LN-2), whatever `txt` is. `json != null && txt == null` → fail. Parse the JSON; for each `(name, start, length)`: `start ≥ 0`, `length ≥ 0`, `start + length ≤ txt.size` else fail ("slice runs past the end"); the name is non-empty and contains no `\t`, `\n` or `\r` else fail; a duplicate key inside one JSON object fails (the parser rejects it). The slice is `txt.copyOfRange(start, start + length)`: **bytes, never decoded** — the stem and the written file are the bytes, so a text that is not valid UTF-8 still round-trips.
- **Stem** = first 16 lowercase hex digits of SHA-256 over the slice bytes. **Key** = first 16 lowercase hex digits of SHA-256 over `name.toByteArray(UTF_8) + 0x00 + stem.toByteArray(UTF_8)` (LN-3).
- **Merge** across AARs on `(name, stem)`: sources = the sorted, de-duplicated artifactIds that carry the pair. The same name with two different texts is two lines (Kotlin 4, J2ObjC 5, Cronet 2 today).
- **Order** (LN-3): by `name.lowercase()` (Kotlin's locale-independent `lowercase()`, never `toLowerCase()` or a `Locale` — this Mac's locale must not change the output), then by `stem`, then by the exact `name` as the final tiebreaker so two names that differ only in case and share a text still sort stably.
- **`indexTsv()`**: UTF-8, no BOM, one line per pair `key\tname\tstem\tsources` with `sources` comma-joined and no spaces, each line ending in a single `\n`, no trailing blank line. The same input in any order yields byte-identical bytes (LN-7 item 1, "permuted").
- **`texts`**: `stem → slice bytes`; the task writes each as `licenses/google/<stem>.txt`, byte for byte.
- Every failure carries the artifactId; the task turns it into `GradleException` naming the AAR file.

### 1.3 The task — `GenerateGoogleNoticesTask`
```kotlin
@CacheableTask
abstract class GenerateGoogleNoticesTask : DefaultTask() {
    @get:InputFiles @get:PathSensitive(PathSensitivity.NAME_ONLY) abstract val aars: ConfigurableFileCollection
    @get:Input abstract val artifactIdsByFileName: MapProperty<String, String>
    @get:OutputDirectory abstract val outputDir: DirectoryProperty    // set by AGP, never by us
    @TaskAction fun generate() { … }
}
```
- **Inputs.** `aars` = the variant's runtime-classpath AAR files; `artifactIdsByFileName` = `aar file name → artifactId`, from the same artifact view's `resolvedArtifacts` (`ModuleComponentIdentifier.module`). The action joins them by `file.name`; a file with no map entry fails naming the file. `NAME_ONLY` because the Gradle cache path is irrelevant and the file name plus its content hash is the identity; `@Input` on the map because the artifactIds are part of the output.
- **Action.** Delete `outputDir` recursively first (stale stems must not survive an SDK bump), then for each AAR open it with `java.util.zip.ZipFile`, read the two **root** entries `third_party_licenses.json` and `third_party_licenses.txt` as bytes (absent → null), hand the list to `GoogleNoticeMerge.merge`, write `licenses/google/index.tsv` and `licenses/google/<stem>.txt` under `outputDir`. The task writes the `licenses/google/` subtree itself: `outputDir` is the root of an assets tree, so the asset path becomes `licenses/google/index.tsv`, beside `licenses/Fredoka-OFL.txt`.
- **Configuration-cache safety.** `gradle.properties` keeps CC off (9.2.7), and the task is written CC-safe anyway so that day's audit finds nothing here: it holds no `Project`, no `Configuration` and no `ResolvedArtifactResult`; its inputs are a `FileCollection` and a `MapProperty` set from providers (`artifactView.files`, `artifactView.artifacts.resolvedArtifacts.map { … }`); the action reads only its own properties. The precompiled plugin's `onVariants` block captures nothing but the variant and the providers.
- **Determinism.** Sorted index, content-addressed stems, bytes copied not decoded, the output directory cleared before each run, no timestamps, no absolute paths in any output. `@CacheableTask` is honest because of this: the same classpath restores the same files from the build cache.
- **Release versus debug.** The plugin registers the task for **every** variant (LN-2), `generateDebugGoogleNotices` and `generateReleaseGoogleNotices`, each over its own `runtimeConfiguration`. Both resolve the same ten Google AARs today (`debugImplementation` adds only `ui-tooling` and `ui-test-manifest`, AndroidX artifacts that carry no `third_party_licenses.json`), so the debug index the JVM tests read equals the release index the AAB carries. Nothing on this branch can assert that equality from inside `:app` (AGP 9.1.0 creates no `testReleaseUnitTest`); checklist 4.6a (d) is the cross-check, on the release artifact, by the release-manager. The `check` task resolves `debugRuntimeClasspath` already, so no new resolution and no network is added to the Check.

### 1.4 The plugin — `google-notices.gradle.kts`
```kotlin
import com.android.build.api.variant.ApplicationAndroidComponentsExtension
import org.gradle.api.artifacts.type.ArtifactTypeDefinition.ARTIFACT_TYPE_ATTRIBUTE

pluginManager.withPlugin("com.android.application") {
    extensions.configure<ApplicationAndroidComponentsExtension> {
        onVariants { variant ->
            val aarView = variant.runtimeConfiguration.incoming.artifactView {
                attributes.attribute(ARTIFACT_TYPE_ATTRIBUTE, AAR_ARTIFACT_TYPE)   // "aar", one constant
            }
            val task = tasks.register<GenerateGoogleNoticesTask>("generate${variant.name.replaceFirstChar(Char::uppercase)}GoogleNotices") {
                aars.from(aarView.files)
                artifactIdsByFileName.set(aarView.artifacts.resolvedArtifacts.map { set -> set.associate { it.file.name to (it.id.componentIdentifier as ModuleComponentIdentifier).module } })
            }
            variant.sources.assets?.addGeneratedSourceDirectory(task, GenerateGoogleNoticesTask::outputDir)
        }
    }
}
```
- Everything named is public API: `Component.runtimeConfiguration`, `SourceDirectories.Layered.addGeneratedSourceDirectory`, Gradle's `ARTIFACT_TYPE_ATTRIBUTE`, `ModuleComponentIdentifier`. **An AGP-internal import stops the developer** (LN-2; tech design §15's row): report it, do not reach for `oss-licenses`.
- `withPlugin` keeps the plugin order-independent; `:app` applies it after `android-app` and `standards` anyway. Only project dependencies resolve to no `aar` artifact (`:domain` is a JVM jar), which is correct: only AARs carry these notices.
- Cast on a non-module identifier (a project or file dependency that somehow matched `aar`) is a failure, not a skip: name the identifier in the message.

### 2.2 The pinning flow — full SHA-256 in LS-AC12, prefix confirmed, release-manager copies
1. Fetch each new text to the scratch directory, not into the repo, with `curl -sS -L -o <scratch>/<name> <url>`; the Jakarta one with `unzip -p`.
2. `shasum -a 256 <file>` and `wc -c <file>`: the first 16 hex digits must equal the research-analyst's prefix and the byte count must equal the size above (the Jakarta one: the prefix `992ed62d` and the suffix `a512214df540`; the Apache one: the full hash). A mismatch is a **stop**: do not commit, report the URL, the size and the hash; the research-analyst, not the developer, decides whether the upstream file moved.
3. Check the file's shape against `.editorconfig` before copying it in: `grep -c ' $'` (trailing whitespace) and `tail -c 1 | od -c` (one final newline). A file that `.editorconfig` would change is still committed **unmodified** — the rule is byte-identical to the source — so the developer copies it with `cp`, never opens it in an editor that applies the config, and re-checks the hash on the committed bytes with `git show HEAD:app/src/main/assets/licenses/<name> | shasum -a 256`. No `.gitattributes` exists, so git normalises nothing; if a fetched file turns out to carry CRLF, report it rather than converting.
4. Pin the **full** hash as a named constant in `BundledLicenseTextHashTest` (§4; one constant per constant of the enum, the two OFL files included, their full hashes read from the committed files and cross-checked against THIRD_PARTY.md §2's prefixes). The test reads each asset **through the real `AssetManager`** (Robolectric), hashes the stream and asserts equality: that is the byte stream `AssetLicenseTextSource` reads and the one the AAB carries, so it also proves AGP's asset merge copies verbatim.
5. The developer's report lists, per file, the URL fetched, the date, the byte count and the full SHA-256. The release-manager copies the full hashes into THIRD_PARTY.md's rows (spec §9 item 8) and into checklist 4.6a (c), which today lists six prefixes and lacks the MPL-2.0 text's `3f3d9e00` (§8, F7).
6. The words grep over the nine curated texts (LS-AC17; nine, not eight — loop 1 F-03) runs as the `UserFacingTextHasNoProtectedNamesTest` of §4; the developer additionally greps the generated `licenses/google/` directory with the same whole-word list and records the count in the report, for the code-auditor's information only — the Google texts are reproduced verbatim and are never edited (spec §3.2, "Never listed").

### 2.3 Where the texts are read, and the re-flow

### A1.2 — (g) Position in the notices list
**Explicit semantics, rows counted alone.** The pinned Foundation's `LazyColumn` publishes list-level `CollectionInfo` with an unknown row count and no per-item `CollectionItemInfo`, so TalkBack says "in list" and no position; and its intro item would otherwise count. The build sets both by hand: on the `LazyColumn`'s modifier, `semantics { collectionInfo = CollectionInfo(rowCount = rows.size, columnCount = 1) }` (the outer semantics modifier's property wins over the lazy layout's own); on each row card, inside its merged node, `semantics { collectionItemInfo = CollectionItemInfo(rowIndex = index, rowSpan = 1, columnIndex = 0, columnSpan = 1) }` with `index` the row's position among the rows (0-based; the intro carries none). TalkBack then announces "N of M" on the last row with M = the index's line count (LS-AC13's device half). The Compose oracle: the list node's `CollectionInfo.rowCount == N`, the last row's `CollectionItemInfo.rowIndex == N − 1`. **Stop condition:** if the test shows the lazy layout's internal `CollectionInfo` overriding the outer one, stop and report — no wrapper `Box`, no custom key.
