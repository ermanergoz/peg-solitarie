<objective>
## Phase Goal (MVP user story)

**As a** peg-solitaire player, **I want to** ask for a hint that reveals a genuine next winning move and undo my last move, **so that** I can get unstuck and keep playing a puzzle that stays fair and always winnable.

## This plan's slice

Deliver the **Hint logic** end-to-end (decision + orchestration), leaving only the pixels to 04-03b: a pure `GetHintUseCase` that returns the next winning move, and the `GameViewModel` orchestration that runs it off the main thread and writes the resulting hint state. Challenge uses the recorded `solution` while on the canonical line (instant, guaranteed, no Solver call); Classic and any post-deviation position fall back to the budgeted `Solver` from 04-02, run on `defaultDispatcher` with a cancellable job and a `solverThinking` flag. The use case is pure `:domain` (cancellation crosses as a plain `shouldCancel` lambda); the VM tracks `onRecordedLine` (recomputed on undo) so it never blind-indexes `solution[moveCount]`.

The **rendering + wiring** of these state fields — `BoardCanvas` highlight, the `HintControl` button + thinking spinner, the D-02 "Show possible moves" rename, and `GameScreen`/`GameRoute` wiring — ships in **04-03b** (its own wave), which reads the `hintSource`/`hintTarget`/`solverThinking` fields this plan sets.

Purpose: ASST-01 (compute the next winning move) + ASST-03 (deviation -> Solver fallback), plus the no-win field feeding 04-04's banner.
Output: pure `GetHintUseCase`, VM hint orchestration (recorded-line tracking + off-thread cancellable job + hint/thinking/no-win `GameUiState` fields), the `DomainModule` provider, and VM/domain tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI tap → ViewModel → Solver (off-thread) | A Hint tap launches CPU-bound Solver work on Dispatchers.Default |
| Hinted move → GameUiState | The move written to hintSource/hintTarget must be a legal move on the current board |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-SD | Denial of Service | onHintRequested Solver job | mitigate | Runs in `withContext(defaultDispatcher)`; `shouldCancel = { !isActive || deadline.hasPassed }` polled by the Solver; `hintJob?.cancel()` before each new request; while `solverThinking` a repeat request cancels the prior job (no overlapping searches / double-taps — the logic half of D-10; the disabled control lands in 04-03b). Structured cancellation alone is insufficient (CPU loop) — the cooperative poll from 04-02 stops it. |
| T-04-CT | Tampering (correctness) | GetHintUseCase recorded branch | mitigate | Recorded move is returned only when in-range AND a member of `RulesEngine.legalMoves(board)` (Pitfall 5); deviation tracked via `onRecordedLine`, recomputed on undo — never blind `solution[moveCount]`. |
| T-04-PU | Information/Boundary | GetHintUseCase purity | mitigate | Use case is pure `:domain` (no coroutines/Android); cancellation crosses as a plain lambda — DomainPurityTest enforces. |

No package installs; no network/auth/crypto/persistence.
</threat_model>
