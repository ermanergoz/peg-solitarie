<objective>
## Phase Goal (MVP user story)

**As a** peg-solitaire player, **I want to** ask for a hint that reveals a genuine next winning move and undo my last move, **so that** I can get unstuck and keep playing a puzzle that stays fair and always winnable.

## This plan's slice

Deliver the **Hint** capability end-to-end: tap Hint → see a genuine next winning move highlighted (source glow + target ring + faint A->B arrow), then the player performs it themselves (never auto-played). Challenge uses the recorded `solution` while on the canonical line (instant, guaranteed); Classic and any post-deviation position fall back to the budgeted `Solver` from 04-02, run off the main thread with a "thinking" indicator. The pre-existing legal-dots toggle is renamed "Show possible moves" so the two affordances are unmistakably distinct (D-02).

Purpose: ASST-01 (hint reveals the next winning move) + ASST-03 (deviation -> Solver fallback). The no-win / stuck banner UI is finished in 04-04; this plan wires the `noWinningMove` state field (set when the hint yields nothing) but leaves its visible banner to the next slice.
Output: pure `GetHintUseCase`, VM hint orchestration (recorded-line tracking + off-thread cancellable job + hint/thinking/no-win fields), `BoardCanvas` highlight rendering, `HintControl`, the D-02 rename, and wiring/tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI tap → ViewModel → Solver (off-thread) | A Hint tap launches CPU-bound Solver work on Dispatchers.Default |
| Hinted move → board render | The move highlighted must be a legal move on the current board |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-SD | Denial of Service | onHintRequested Solver job | mitigate | Runs in `withContext(defaultDispatcher)`; `shouldCancel = { !isActive || deadline.hasPassed }` polled by the Solver; `hintJob?.cancel()` before each new request; Hint disabled while `solverThinking` (no overlapping searches / double-taps, D-10). Structured cancellation alone is insufficient (CPU loop) — the cooperative poll from 04-02 stops it. |
| T-04-CT | Tampering (correctness) | GetHintUseCase recorded branch | mitigate | Recorded move is returned only when in-range AND a member of `RulesEngine.legalMoves(board)` (Pitfall 5); deviation tracked via `onRecordedLine`, recomputed on undo — never blind `solution[moveCount]`. |
| T-04-PU | Information/Boundary | GetHintUseCase purity | mitigate | Use case is pure `:domain` (no coroutines/Android); cancellation crosses as a plain lambda — DomainPurityTest enforces. |

No package installs; no network/auth/crypto/persistence.
</threat_model>
