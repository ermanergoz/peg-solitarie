<objective>
Persist the cadence state so the frequency cap survives the app being killed (INT-02's
"survives being killed"), and source the 30-minute session boundary from real app
foreground/background rather than from Activity lifecycle.

Purpose: the pure policy from 10-01 decides; this plan is the only thing that remembers.
D-13 splits the state deliberately — five scalars on disk, the per-session count in memory —
and D-16 pins the session signal to `ProcessLifecycleOwner` because
`DefaultForegroundActivityProvider` clears on `onActivityPaused`, which fires on every
fullscreen ad and would forge a "backgrounded" event that resets the D-04 cap on each show.

Output: `InterstitialCadenceStore` (shared `app_prefs`, fail-open reads, best-effort writes),
`AppForegroundTracker`, its registration in `App.onCreate`, the `lifecycle-process` catalog
entry, and the two test files that prove the persistence contract.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| on-disk `app_prefs` -> app process | Preferences are world-writable to a rooted device owner and corruptible by an interrupted write. |
| Android lifecycle callbacks -> session state | `ON_START`/`ON_STOP` arrive from the framework; a fullscreen ad Activity is the specific event source that must NOT be read as a background. |
| new Maven artifact -> build | `androidx.lifecycle:lifecycle-process` enters the dependency graph. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `InterstitialCadenceStore.state` read path | mitigate | Every read goes through `InterstitialCadenceState.fromStored`, which clamps and fails toward fewer ads; a `catch { emit(emptyPreferences()) }` turns a corrupt store into the default state rather than a crash. |
| T-10-10 | Denial of Service | `InterstitialCadenceStore` writes | mitigate | Every `dataStore.edit` is wrapped in `storageFailSafe(fallback = Unit)`; an unguarded IO failure on the app-lifetime `SupervisorJob` scope crashes the app (documented in-repo as T-05-13). Proven by the `throwingWriteDataStore()` case. |
| T-10-11 | Spoofing | session boundary event source | mitigate | `ProcessLifecycleOwner` only, never `DefaultForegroundActivityProvider` (D-16). | T-10-12 | Tampering | lost update on concurrent writes | mitigate | The merge is computed inside the `dataStore.edit` transaction from the transaction's own `preferences`, never from the cached `state.value` — the `ChallengeProgress.advancePast` precedent. |
