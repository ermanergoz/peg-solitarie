    Each gate independently necessary (four tests, one field flipped per test):
    - `winsSinceLastInterstitial = WINS_BETWEEN_INTERSTITIALS - 1` -> false (D-01)
    - `nowMs - lastFullscreenAdAtMs = MIN_GAP_MS - 1` -> false (D-02)
    - `firstSessionComplete = false` (with lifetime levels far past the threshold) -> false (D-03)
    - `lifetimeCompletedLevels = SUPPRESSED_FIRST_LEVELS - 1` (with firstSessionComplete = true)
      -> false (D-03: BOTH halves, whichever ends later)
    - `interstitialsThisSession = MAX_PER_SESSION` -> false (D-04)

    Boundaries are inclusive on the passing side:
    - wins == WINS_BETWEEN_INTERSTITIALS -> true; elapsed == MIN_GAP_MS -> true;
      lifetime == SUPPRESSED_FIRST_LEVELS -> true; session == MAX_PER_SESSION - 1 -> true.

    Clock edges (D-02):
    - `lastFullscreenAdAtMs == NEVER_SHOWN` passes the D-02 gate at any nowMs — a player who has
      never seen a fullscreen ad has trivially waited long enough.
    - `nowMs < lastFullscreenAdAtMs` (a backwards clock, or a forged future stamp) passes the
      D-02 gate rather than locking it forever.

    Transitions:
    - `recordWin()` increments BOTH `winsSinceLastInterstitial` and `lifetimeCompletedLevels`
      and touches nothing else (D-07: one shared counter, both modes).
    - `recordWin()` saturates: from `winsSinceLastInterstitial = WINS_BETWEEN_INTERSTITIALS` it
      stays there, and from `lifetimeCompletedLevels = SUPPRESSED_FIRST_LEVELS` it stays there —
      called `Int.MAX_VALUE` times it can never overflow (ASVS V5).
    - `recordInterstitialShown(nowMs)` zeroes `winsSinceLastInterstitial`, sets
      `lastFullscreenAdAtMs = nowMs`, increments `interstitialsThisSession` (saturating at
      `MAX_PER_SESSION`), and leaves `lifetimeCompletedLevels` / `firstSessionComplete` alone.
    - `recordRewardedShown(nowMs)` sets `lastFullscreenAdAtMs = nowMs` and changes NOTHING else
      (D-15) — and a state that satisfied every gate before it no longer satisfies D-02 at the
      same nowMs afterwards. This is the D-15 adjacency test: assert it by name.
    - `startNewSession()` sets `interstitialsThisSession = 0` and `firstSessionComplete = true`.

    Session boundary (`isNewSession(lastForegroundAtMs, nowMs)`, D-04/D-16):
    - gap == SESSION_GAP_MS -> true; gap == SESSION_GAP_MS - 1 -> false.
    - `lastForegroundAtMs == NEVER_FOREGROUNDED` -> false (a first-ever launch closes no prior
      session; if it returned true, D-03's first-session suppression would end on launch one).
    - `nowMs < lastForegroundAtMs` (backwards/forged clock) -> false, so the D-04 cap keeps binding.

    Validate-on-read (`fromStored`, ASVS V5, fail toward FEWER ads):
    - All-null (fresh install / corrupt store) -> the default state, and `mayShow` on it is false.
    - A negative stored `winsSinceLastInterstitial` / `lifetimeCompletedLevels` -> 0.
    - A stored counter above its threshold (a forged `9999`) -> clamped to its threshold, never
      rejected upward.
    - A stored `lastFullscreenAdAtMs` that is negative and not exactly `NEVER_SHOWN` -> `NEVER_SHOWN`.
    - A stored `lastFullscreenAdAtMs` of `Long.MAX_VALUE` -> `NEVER_SHOWN` (so no later
      `nowMs - lastFullscreenAdAtMs` can overflow).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| persisted store -> cadence state | Values read back from DataStore are attacker-writable on a rooted device and corruptible on any device; they enter the policy through `fromStored`. |
| device wall clock -> cadence gates | `nowMs` and the persisted stamps come from a clock the user controls and an NTP correction can move backwards. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-01 | Tampering | `InterstitialCadenceState.fromStored` | mitigate | Validate on read, clamp to the declared range, fail toward FEWER ads (`firstSessionComplete` defaults to `false`, so a corrupt store shows no interstitial). Tested by the four `fromStored` cases. |
| T-10-05 | Denial of Service | `recordWin` / `recordInterstitialShown` counters | mitigate | Saturating `coerceAtMost` at each counter's own threshold makes `Int` overflow unreachable; the counters are only ever compared with `>=`, so nothing is lost. |
| T-10-07 | Tampering | `enoughElapsed` / `isNewSession` clock deltas | mitigate | A negative delta opens the D-02 gate (no permanent lockout, no forged-future suppression) and closes the session boundary (the D-04 cap keeps binding). Both directions are tested. |
| T-10-08 | Tampering | Long-overflow via a forged `lastFullscreenAdAtMs` | mitigate | `fromStored` maps `Long.MAX_VALUE` and any negative value other than `NEVER_SHOWN` to `NEVER_SHOWN`, so `nowMs - lastFullscreenAdAtMs` can never overflow. |
| T-10-09 | Information disclosure | anything in the cadence path | mitigate | No logging call in `:domain`'s ads package — ad-adjacent values are personal-data-adjacent (ASVS V7) and the in-repo ad path already forbids naming a logging API. |
| T-10-SC | Tampering | dependency installs | mitigate | This plan adds NO dependency. RESEARCH.md § Package Legitimacy Audit approved all three phase artifacts as first-party Google/AOSP on Google Maven with no `[ASSUMED]`/`[SUS]` verdicts, so no legitimacy checkpoint is required. |
