<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UI taps → GameViewModel | A tap-derived `Position` is untrusted input; the VM must re-decide legality, never apply a UI-asserted move |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `GameViewModel.onCellTap` applying an illegal/forged move | mitigate | The VM rebuilds `legalTargets` from `RulesEngine.legalMoves(board)` on every selection and applies a `Move` ONLY if the tapped destination is in that set; otherwise no-op. RulesEngine is the single authority. Asserted by a `GameViewModelTest` case (illegal tap → unchanged state). |
| T-03-02 | Tampering | Game-over modeled as a one-shot effect (lost on rotation, or replayed incorrectly) | mitigate | Game-over is `GameUiState.status` (replayable state), not a `Channel` effect — survives config changes and is re-rendered idempotently (RESEARCH Anti-Pattern). |

**Honest assessment:** Single-player offline logic; the only untrusted input is a local tap. No high-severity threats. The meaningful control is that the VM never trusts the UI to submit a legal move — enforced in code and by test.
</threat_model>
