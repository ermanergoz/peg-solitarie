## The exact `createSql` copied into `MIGRATION_1_2`

Transcribed from `2.json`'s `play_session` entity with only `${TABLE_NAME}` replaced by the literal table name. A reviewer can diff this against the committed JSON without running a build:

```sql
CREATE TABLE IF NOT EXISTS `play_session` (`id` INTEGER PRIMARY KEY AUTOINCREMENT NOT NULL, `mode` TEXT NOT NULL, `levelId` TEXT NOT NULL, `stars` INTEGER NOT NULL, `score` INTEGER NOT NULL, `elapsedMs` INTEGER NOT NULL, `hintsUsed` INTEGER NOT NULL, `undosUsed` INTEGER NOT NULL, `lastPegOnTarget` INTEGER NOT NULL, `finishedAt` INTEGER NOT NULL)`
```

(The trailing backtick above is markdown fence noise; the statement ends at the closing parenthesis.) In the source it is split across five `+`-concatenated literals to respect `max_line_length = 120`; the concatenation was machine-diffed against the JSON and matches byte-for-byte.

Note `lastPegOnTarget` is `INTEGER NOT NULL` — Kotlin `Boolean` maps to `INTEGER`, so plan 12-06's SQL predicates must compare against `1`/`0`, never `true`/`false`.

## `play_session` has no call site yet

This is deliberate and is not an oversight. `PlaySessionDao.insert` is intentionally unused until plan **12-06**, which will call it inside `ProgressRepository.recordResult`'s transaction so the best-row upsert and the telemetry append commit together (D-08). This plan writes no aggregate SQL, no `SolveTelemetry` type, and no change to `recordResult`'s signature.

## Decisions Made

- **Named DDL constant over an inline string literal.** The plan allowed either; a `private const val CREATE_PLAY_SESSION_SQL` gives the QUAL-03 exception note a natural home and keeps `migrate` to the single `execSQL` call the plan requires.
- **`RuntimeEnvironment.getApplication()` over `ApplicationProvider.getApplicationContext()`.** `androidx.test:core` is only a transitive dependency here, while `RuntimeEnvironment` is already the established way this codebase obtains a Robolectric `Context` (see `PegSolitaireDatabaseTest`). The load-bearing part of the assertion — calling the real `DatabaseModule` provider rather than a hand-rolled builder — is unchanged.
- **Seed/select SQL extracted to file-private constants.** detekt's `MagicNumber` actually excludes `**/test/**`, so this was not strictly forced, but it keeps the seeded literals named and matches the plan's Pitfall 13 instruction.

**2. [Rule 1 - Bug] `PlaySessionDao` KDoc prose defeated its own acceptance grep**

- **Found during:** Task 1 (acceptance-criteria verification loop)
- **Issue:** The KDoc explaining why no read query exists contained the literal token `@Query`, so `grep -c "@Query" PlaySessionDao.kt` returned 1 instead of the required 0. The gate is meant to prove no query is *declared*; a prose mention made it unfalsifiable in the wrong direction.
- **Fix:** Reworded the sentence to "declaring a speculative read" so the grep measures real declarations only.
- **Files modified:** `app/src/main/java/com/app/pegsolitaire/data/db/PlaySessionDao.kt`
- **Verification:** `grep -c "@Query"` is now 0; `grep -c "@Insert"` is 1.
- **Committed in:** `39b4191` (Task 1 commit)
