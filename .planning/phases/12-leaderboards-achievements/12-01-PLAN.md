<objective>
Land the Room v1 -> v2 schema migration that makes per-session play telemetry storable (PGSA-06),
so PGSA-02's skill achievements become derivable in later plans. The migration is a pure additive
`CREATE TABLE play_session` — `level_result` and `resume_snapshot` are not touched at all — and it
ships with the exported `2.json` and two `MigrationTest` cases: one proving v1 rows survive, one
proving the migration is actually **registered** on the production Room builder.

Purpose: the ROADMAP Phase 12 note requires the telemetry migration to land **before or with** any
achievement wiring, proven progress-preserving with a `MigrationTestHelper` test. This is that
plan, and it is the only Phase 12 plan that touches the schema.
Output: `PlaySessionEntity`, an insert-only `PlaySessionDao`, `DB_VERSION = 2`, `MIGRATION_1_2`
registered in `DatabaseModule`, a committed `2.json`, and a `MigrationTest` with two real cases.

**Boundary — explicitly NOT this plan:** no aggregate/projection SQL, no `ProgressAggregate`, no
change to `ProgressRepository.recordResult`'s signature or transaction, no `SolveTelemetry` type,
no achievement or `GamesService` wiring, no `GameViewModel`/nav-arg change. D-08's "one transaction
writing both tables" is plan **12-06** and only rides on the table this plan creates. Do not write
a call site for `PlaySessionDao.insert` here — it is deliberately unused until 12-06.
</objective>
