# Phase 2 — UI Design Contract

> Visual and interaction contract for the **five-screen Classic-mode flow** (Home → Classic catalog → Gameplay → Results) plus the first-run **onboarding overlay**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a native Android **Jetpack Compose + Material 3** game (Compose BOM 2026.06.00), **not** a web/shadcn project — there is no component registry. Screens are built from Material 3 composables (`Scaffold`, `TopAppBar`, `Card`, `Button`, `OutlinedButton`, `TextButton`, `Icon`, `LazyVerticalGrid`, scrim+`Surface` for the overlay); the board itself is the Phase-1 Compose `Canvas` (`BoardCanvas`), reused unchanged for gameplay and as the catalog mini-preview.
>
> **Hard project constraints baked into this contract (CLAUDE.md / QUAL-03), identical to Phase 1:**
> - Every fixed dp/sp value is a `res/values/dimens.xml` token — no raw dp/sp literal in any composable (the `dpSpLiteralCheck` gate fails the build on one).
> - Every color is a **Material 3 theme role** (`MaterialTheme.colorScheme.*`) — no hex literal in composables.
> - Every type style is an M3 role (`MaterialTheme.typography.*`) — no raw sp literal; exactly **two weights** (Regular 400 + Medium 500).
> - Unitless values (board ratios, animation ms, per-board grid dimension) live in **scoped constants objects** (`BoardMetrics`, `GameAnim`), never inline.
> - All user-facing copy lives in `res/values/strings.xml` (no magic strings); counts are plural-aware.
> - All composables stateless / state-hoisted; each screen's `ViewModel` owns one immutable UiState over `StateFlow`. New screens follow the Phase-1 **Route → Screen → Leaf** shape.

## Spacing Scale

8-point scale (all multiples of 4), declared as `dimens.xml` tokens. **Reuse the Phase-1 tokens**; add only the genuinely new layout tokens below. Board geometry that scales with canvas size stays as **ratios** in `BoardMetrics`, never dp.

**Existing tokens (reuse as-is):**

| Token (dimens.xml) | Value | Usage this phase |
|--------------------|-------|------------------|
| `spacing_xs` | 4dp | Star-to-star gap; inline icon/label gaps |
| `spacing_sm` | 8dp | Badge inner padding; metric label→value gap |
| `spacing_md` | 16dp | Default screen/edge padding; grid cell spacing; card inner padding |
| `spacing_lg` | 24dp | Section breaks; results metric-block spacing; overlay sheet padding |
| `spacing_xl` | 32dp | Vertical breathing room above the results headline / between major blocks |
| `board_screen_margin` | 16dp | Board outer margin (gameplay, unchanged) |
| `board_max_size` | 480dp | Board square cap (gameplay, unchanged) |
| `board_min_touch_target` | 48dp | M3 minimum touch target — every interactive cell/tile/button honors this |
| `top_bar_icon_size` | 24dp | Top-bar action/nav icon size |

**New tokens to add (multiples of 4):**

| Token (dimens.xml) | Value | Usage |
|--------------------|-------|-------|
| `content_max_width` | 480dp | Caps the content column width on Home / Catalog / Results so they don't sprawl on tablets (mirrors `board_max_size`, distinct semantic) |
| `mode_tile_min_height` | 96dp | Min height of the Home Classic / Challenge mode tiles (comfortable tap target + room for label + badge) |
| `catalog_grid_min_cell_width` | 160dp | `LazyVerticalGrid(GridCells.Adaptive(min))` minimum card width — 1 column on phones, 2+ on wider screens |
| `catalog_preview_size` | 96dp | Square edge of the mini `BoardCanvas` preview inside each catalog card |
| `results_star_size` | 48dp | Rendered size of each of the 3 result stars (earned + unearned) |
| `onboarding_illustration_size` | 160dp | Square edge of each onboarding step's jump illustration |

Exceptions: board cell size, peg/hole/dot/ring radii are **computed from canvas size** and live as unitless ratios in `BoardMetrics` (NOT dimens.xml) — unchanged from Phase 1, and now generalized so `GRID_DIMENSION` is **derived per board** (7 for English/European, 8 for Asymmetric-39, 9 for Diamond-41/Wiegleb-45) instead of the hardcoded `7` (D-18). The two stroke-width tokens (`peg_selected_ring_width` 3dp, `hole_outline_width` 1dp) remain the documented sub-4dp rendering exception from Phase 1. Card corner radius and badge shape use M3 shape roles (`MaterialTheme.shapes.large` / `.small`), not dp tokens.

## Typography

Material 3 type-scale roles only (no invented sizes). Exactly **two weights** across the phase: Regular (400) + Medium (500) — preserved from Phase 1.

| Role in UI | M3 token | Size / Weight / Line-height (M3 default) | Usage |
|------------|----------|------------------------------------------|-------|
| Results headline (the payoff) | `displaySmall` | 36sp / Regular 400 / 44sp | Star-tier headline "Perfect!" / "Solved!" / "Stuck" (D-08) |
| Screen / top-bar title | `titleLarge` | 22sp / Medium 500 / 28sp | "Peg Solitaire" (Home), "Classic" (catalog top bar), "Results" |
| Card / tile title | `titleMedium` | 16sp / Medium 500 / 24sp | Board name on a catalog card; "Classic" / "Challenge" on Home tiles |
| Metric value | `titleLarge` | 22sp / Medium 500 / 28sp | The numeric score, elapsed time, pegs-remaining values on Results |
| Timer (top bar, gameplay) | `titleMedium` | 16sp / Medium 500 / 24sp | Live `mm:ss` elapsed clock (D-04) |
| Body | `bodyMedium` | 14sp / Regular 400 / 20sp | Hole-count subtitle; onboarding caption; supporting copy |
| Onboarding step body | `bodyLarge` | 16sp / Regular 400 / 24sp | The how-to-play explanatory sentence per step |

| "Coming soon" badge | `labelSmall` | 11sp / Medium 500 / 16sp | The disabled-Challenge badge text (D-09) |

Weights used: **400 (Regular)**, **500 (Medium)** — two only. Reused Phase-1 roles (`titleLarge`, `bodyMedium`, `labelLarge`) are unchanged.

## Color

Material 3 role mapping for the 60/30/10 balance, consistent with Phase 1. Surfaces are the 60% dominant mass; cards/tiles/board panels are the 30% secondary mass; `primary` is the strictly-reserved 10% accent.

| Role | M3 token | Usage |
|------|----------|-------|
| Dominant (60%) | `surface` / `background` | Every screen background; the scrim-backed area behind the onboarding sheet uses `scrim` |
| Secondary (30%) — tiles & cards | `surfaceContainerHigh` | Home mode tiles, catalog board cards, the onboarding sheet, the board panel (gameplay, unchanged) |
| Secondary (30%) — recessed slots | `surfaceContainerLowest` | Catalog mini-preview backing; empty-hole fill (board, unchanged) |
| Secondary (30%) — pegs (resting) | `secondary` | Game pieces in gameplay AND in the catalog mini-preview |
| Accent (10%) — primary actions | `primary` (filled `Button`) | The ONE primary CTA per screen: Home "Play Classic", Results "Next board", Onboarding "Got it" |
| Accent (10%) — earned star | `primary` (filled `Icons.Rounded.Star`) | Each star the player earned on Results |
| Accent (10%) — gameplay selection | `primary` ring + `primary`@38% dots | Selected-peg ring + legal-destination dots (reused verbatim from Phase 1) |
| Accent (10%) — onboarding highlight | `primary` (the jump arrow / target-hole highlight in the illustration) | Draws the eye to the move being taught |
| Unearned star | `outlineVariant` (`Icons.Rounded.StarBorder`) | The 1–2 stars the player did NOT earn — outline, never filled accent |
| "Coming soon" badge | container `secondaryContainer` + text `onSecondaryContainer` | Disabled-Challenge badge (D-09) — deliberately NOT accent |
| Disabled Challenge tile content | `onSurface` @ M3 disabled alpha (`Modifier`/`enabled=false`) | The whole Challenge tile reads as inert |
| On-content text | `onSurface` / `onSurfaceVariant` | Titles & values `onSurface`; metric labels, hole counts, captions `onSurfaceVariant` |
| Secondary actions (Results) | `OutlinedButton` / `TextButton` with `onSurface` label, `outline` border | "Replay", "Catalog", "Home" — neutral, never accent |
| Nav-up / help / restart icons | `onSurface` (top-bar `IconButton` tint) | Back arrow, How-to-play, gameplay restart |
| Destructive | **none** — see note | — |

**Accent (`primary`) reserved for, and nothing else:**
1. The single primary CTA button on each screen (Home "Play Classic", Results "Next board", Onboarding "Got it").
2. Earned stars on the Results screen.
3. The gameplay selection accent (selected-peg ring + legal-destination dots) — reused from Phase 1.
4. The onboarding jump-arrow / highlighted target hole in the illustration.

The "Coming soon" badge, all secondary/text buttons, the back/help icons, hole counts, and the 30% peg mass are explicitly **not** accent. At any moment `primary` is at most one filled button + ≤3 stars (or the gameplay selection set) — comfortably under 10%.

**Destructive color note (carried from Phase 1):** Phase 2 still has **no `error`/red anywhere**. "Replay" and "Next board" act on an already-finished game (nothing to destroy). Leaving an in-progress game via the back arrow loses unsaved progress, but per casual-game feel this is **not** styled destructively and — pending the Phase-5 resume layer — is allowed without an extra confirm (see Interaction Contract → Open Assumption A-1). A benign navigation should not alarm a casual player.

## Screen Contracts

### 1. Home (mode select) — NAV-01, D-09/D-10/D-14/D-15

- **Layout:** `Scaffold` with a `TopAppBar` (title "Peg Solitaire", a trailing **How to play** `IconButton` `Icons.Rounded.HelpOutline`, content description "How to play"). Body is a single centered column, capped at `content_max_width`, padded `spacing_md`, holding two stacked mode tiles separated by `spacing_md`.
- **Classic tile (enabled):** `surfaceContainerHigh` `Card`, `mode_tile_min_height`, title "Classic" (`titleMedium`), supporting line "5 boards" (`bodyMedium`, `onSurfaceVariant`). Whole tile is the tap target → navigates to `ClassicCatalog`. (The phase's primary CTA accent; if rendered as a filled action it uses `primary`, otherwise the tile is the clear primary affordance.)
- **Challenge tile (disabled, D-09):** identical footprint, `enabled = false`, content at disabled alpha, with a `secondaryContainer` **"Coming soon"** pill badge (`labelSmall`, top-right). No navigation, no route built. Reserves the slot so Home's layout is unchanged when Phase 3 lands.
- **Onboarding trigger (D-14):** on first launch only (`onboardingSeen == false`), the onboarding overlay (screen 5) is shown over Home once; dismissing it calls `markSeen()`. The How-to-play affordance (D-15) re-opens the same overlay any time, independent of the flag.
- **Focal point:** the two centered tiles are the sole content; the enabled Classic tile is visually dominant (the disabled Challenge tile recedes via alpha).

### 2. Classic catalog — CLAS-01, D-11/D-18

- **Layout:** `Scaffold` with a `TopAppBar` (title "Classic", back-arrow navigation icon → Home). Body is a `LazyVerticalGrid(GridCells.Adaptive(catalog_grid_min_cell_width))`, content padding `spacing_md`, both arrangements `spacing_md` — 1 column on phones, 2+ on wider screens.
- **Order (D-18, ascending hole count):** English-33 (33) → European-37 (37) → Asymmetric 3-3-2-2 (39) → Diamond-41 (41) → Wiegleb-45 (45). This same order defines the Results "Next board" wrap (D-06).
- **Card (per board):** `surfaceContainerHigh` `Card` (`MaterialTheme.shapes.large`), inner padding `spacing_md`. Top: a **mini `BoardCanvas` preview** (`catalog_preview_size` square, on a `surfaceContainerLowest` backing, `MaterialTheme.shapes.large` clip). Below: board name (`titleMedium`, `onSurface`) + hole count e.g. "33 holes" (`bodyMedium`, `onSurfaceVariant`, plural-aware). Whole card taps → `Gameplay(levelId)`.
- **Mini-preview contract (reuses `BoardCanvas`):** renders the board's footprint **statically** — resting pegs filled `secondary`, the single start-empty hole recessed (`surfaceContainerLowest` + `outlineVariant` ring), **no** legal-destination dots, **no** selection ring, **no** animation, and **not tappable** (it does not emit `onCellTap`; the parent `Card` owns the tap). The planner decides the mechanism (a read-only flag/param on `BoardCanvas` or a thin preview wrapper) but the visual + non-interactive contract above is fixed. The preview also doubles as a free smoke test that each new `BoardSpec` footprint (dims 7/8/9, incl. the off-center Asymmetric-39) lays out correctly.
- **Empty state:** **N/A** — the catalog is a fixed 5-board set, never data-empty.

### 3. Gameplay — CLAS-02, SCOR-02, D-04

- Reuses the Phase-1 `GameScreen`/`BoardCanvas` **unchanged** for the board, selection, jump (D-07) and removal (D-08) animations, and the top-bar restart control (`Icons.Rounded.Refresh`, mid-game confirm D-06). The board now comes from the selected `levelId` via the repository, not a hardcoded inject.
- **New: visible elapsed timer (D-04).** A live `mm:ss` `Text` (`titleMedium`, `onSurface`) in the `TopAppBar` (e.g. as the title or a leading element, optionally prefixed with `Icons.Rounded.Schedule`), content description "Elapsed time". The clock starts on the first move, ticks once per second, and **stops** on terminal status. It is the input to the D-03 score. The top bar now also carries a back-arrow → Catalog.
- **Terminal transition (replaces P1 dialog):** when status transitions to `Won`/`Stuck`, gameplay navigates **once** to `Results(...)` (one-shot effect, never a per-recomposition re-navigate). `GameOverDialog`/`GameOverOverlay` are removed.

### 4. Results — SCOR-01/02/03, D-05/D-06/D-07/D-08

- **Layout:** full dedicated destination. `Scaffold` (top bar title "Results", back-arrow → Catalog). Body is a centered column capped at `content_max_width`, padded `spacing_md`, vertical arrangement `spacing_lg`:
  1. **Star-tier headline** (`displaySmall`, `onSurface`) — copy by tier (D-08, see Copywriting).
  2. **Star row** — 3 stars, `results_star_size`, `spacing_xs` apart; earned = filled `Icons.Rounded.Star` `primary`, unearned = `Icons.Rounded.StarBorder` `outlineVariant`. A "stuck" loss (D-07) renders here too, typically 1★ — same screen, no separate loss UI.
  3. **Metric block** — three labeled values (`titleLarge` value over `labelMedium` `onSurfaceVariant` caption): **SCORE** (numeric, SCOR-02/03), **TIME** (`mm:ss`), **PEGS LEFT** (plural-aware). Stars and score are independent axes (D-01 vs D-03) — both shown.
  4. **Actions (D-06):** primary filled `Button` **"Next board"** (`primary`) → next catalog board, wrapping at the end; plus secondary `OutlinedButton`/`TextButton` **"Replay"** (same board), **"Catalog"**, **"Home"**. Exactly one primary accent; the rest neutral.
- **Inputs:** all values arrive as typed route args (`stars`, `pegsRemaining`, `elapsedSeconds`, `score`, `levelId`); `stars`/`score` are computed by the pure-domain `ScoreCalculator` at game end (never in the composable).

### 5. Onboarding overlay — ONB-01, D-13/D-14/D-15

- **Layout:** a dismissable overlay over Home (not a route): a `scrim`-filled `Box` + a centered `surfaceContainerHigh` `Surface` sheet (`MaterialTheme.shapes.large`, padding `spacing_lg`, capped `content_max_width`).
- **Content:** a few illustrated steps teaching the orthogonal jump — a peg hops an adjacent peg into an empty hole; the jumped peg is removed. Each step: an `onboarding_illustration_size` illustration (drawn with the same board roles — pegs `secondary`, empty hole recessed, the jump arrow / target highlight in `primary`) + a one-sentence `bodyLarge` caption.
- **Dismissal (skippable, D-13):** a primary `Button` **"Got it"** and a `TextButton` **"Skip"** — both dismiss and call `markSeen()`. Re-openable any time via the Home How-to-play affordance (D-15).
- **First-run gate (D-16):** shown automatically only while `onboardingSeen == false`; the flag is a single DataStore-Preferences boolean. If the flag read fails, treat as not-seen (fail-open to teaching).

## Board Geometry — generalization note (square grid only, D-18)

The Phase-1 `BoardMetrics.GRID_DIMENSION = 7` is **English-33-specific**. For the four new boards the only geometry change is **deriving the grid dimension per board** from the `BoardSpec` bounds (`max(rows, cols)`): European-37 = 7, Asymmetric 3-3-2-2 = 8 (off-center footprint inside an 8×8 box — render the box as-is), Diamond-41 = 9, Wiegleb-45 = 9. No `BoardLattice`/triangle strategy (Triangle-15 dropped, D-17). `BOARD_ASPECT_RATIO = 1f` and every ratio constant stay unchanged; `positionAt` stays bounds-checked for every footprint. This is a `BoardMetrics`/`BoardGeometry` concern (scoped constants), not a dimens.xml or color change.

## Interaction & Animation Contract

- **Navigation (NAV-02):** type-safe `NavHost` in `MainActivity`. `Home` (start) → `ClassicCatalog` → `Gameplay(levelId)` → `Results(...)`. Back arrows: Catalog→Home, Gameplay→Catalog, Results→Catalog. Results actions: "Next board" → `Gameplay(nextId)` (catalog order, wraps, D-06), "Replay" → `Gameplay(sameId)`, "Catalog" → pop to `ClassicCatalog`, "Home" → pop to `Home`. The terminal-status → Results navigation is a **one-shot** effect (never fires on recomposition).
- **Gameplay tap/animation:** unchanged from Phase 1 (two-step select-then-jump, D-02/03; deselect-by-retap; no-op on illegal cell; `JUMP_SLIDE_MS`/`REMOVAL_MS`/`SELECT_FADE_MS` in `GameAnim`). Catalog mini-previews are **non-interactive** (no taps, no animation).
- **Timer:** starts on first move, 1 Hz tick, stops at terminal status; survives rotation (computed from a monotonic mark in the `ViewModel`). Process-death persistence is Phase 5 — not persisted now.
- **Onboarding:** appears once on first launch over Home; "Got it"/"Skip" both dismiss + persist seen; How-to-play re-opens it any time.
- **Open assumption A-1 (flagged, non-blocking):** leaving an **in-progress** game via the gameplay back arrow discards unsaved progress without a confirm dialog (no persistence/resume until Phase 5). Recommended for casual feel; revisit when Phase 5 adds resume. CONTEXT does not lock this, so it is recorded as an assumption rather than a blocker.
