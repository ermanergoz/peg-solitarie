# Phase 9 — UI Design Contract

> Visual and interaction contract for the Consent & Rewarded Ads phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Platform note:** This is a native **Android / Jetpack Compose + Material 3** project, not a web/React app. The shadcn initialization gate is **not applicable** (shadcn is a React/Next/Vite tool). The design system is the shipped **"Candy Clay"** system — `docs/ui/DESIGN-SYSTEM.md` + `ui/theme/{Color,Type,Clay,ClayAnim,Theme}.kt` + `res/values/dimens.xml` + `res/values/strings.xml`. This spec **extends** those tokens for the four new Phase-9 surfaces; it does not re-specify what already exists.
>
> **Two surfaces in this phase are NOT styleable by the app and are deliberately outside this contract:** the **UMP consent form** (server-configured in the AdMob Privacy & messaging UI, rendered by the UMP SDK) and the **rewarded ad creative itself** (rendered fullscreen by GMA Next-Gen). The app's visual responsibility begins and ends at the surfaces listed below.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (native Android; shadcn N/A) |
| Preset | not applicable |
| Component library | Material 3 (Compose BOM 2026.06.00) + the in-repo Candy Clay toolkit (`Modifier.claySquish()`, `Modifier.clayShadow()`, `Modifier.clayEntrance()`, `Modifier.goldGradientFill()`, `ctaGradientBrush()`) |
| Icon library | `androidx.compose.material:material-icons-core` — **core set only** (extended set banned; local `ImageVector`s authored when core lacks a glyph, e.g. `UndoIcon.kt`) |
| Font | **Fredoka** (headings/display, 500–600) + **Nunito** (body/labels, 400–700) via downloadable Google Fonts, with permanent platform-default fallback on resolution failure |

**Governing rule (CLAUDE.md QUAL-03, build-gated):** no hex reaches a composable except through `MaterialTheme.colorScheme.*` / `LocalClayColors.current`; no fixed dp/sp reaches a composable except through `dimensionResource(...)` (`dpSpLiteralCheck` fails the build on a raw literal); all copy in `strings.xml`; all durations/ratios in scoped constants objects. Ad-unit IDs are the one established exception — they live in `BuildConfig` via `AdIds`, never in a constants object (`adIdLiteralCheck`).

## Spacing Scale

Declared in `app/src/main/res/values/dimens.xml` (8-point grid, all multiples of 4). **Reuse these — Phase 9 introduces no new spacing token.**

| Token | Value | Phase-9 usage |
|-------|-------|---------------|
| `spacing_xs` | 4dp | Label ↔ supporting-line gap inside a Settings privacy row |
| `spacing_sm` | 8dp | Gap between the two dialog action buttons; section-header inset |
| `spacing_md` | 16dp | Dialog content vertical rhythm; Settings row inner padding; gap between Settings cards |
| `spacing_lg` | 24dp | Dialog surface inner padding; dialog horizontal screen margin |
| `spacing_xl` | 32dp | (not used this phase) |

Reused fixed tokens (not new): `content_max_width` = 480dp (caps the dialog width and the Settings column), `settings_row_min_height` = 72dp (each new privacy row), `elevation_dialog` = 12dp (dialog `clayShadow`), `elevation_card` = 6dp (snackbar + Settings card `clayShadow`), `shape_corner_*` (consumed via `MaterialTheme.shapes`).

**New for Phase 9 — exactly three dimen tokens, all multiples of 4, each with a distinct semantic owner:**

| New token | Value | Why it exists |
|-----------|-------|---------------|
| `ad_offer_glyph_size` | 48dp | The gold reward glyph at the top of the opt-in dialog. Not `results_star_size` (also 48dp) — that token means "a Results star" and must stay free to move. |
| `ad_offer_progress_size` | 24dp | The in-button loading spinner during the D-10 bounded wait. Not `top_bar_icon_size` — that token is top-bar-scoped (`HintControl`'s thinking spinner owns it). |
| `settings_row_icon_size` | 24dp | The trailing "opens externally" glyph on the Privacy policy row. Not `top_bar_icon_size` — this icon is inside a list card, not a top bar. |

**Exceptions:** none added. The pre-existing intentional sub-4dp exception (`peg_selected_ring_width` = 3dp) and the contract-fixed off-grid values (`shape_corner_extra_small` 12dp, `elevation_card` 6dp, `elevation_dialog` 12dp) are untouched.

## Typography

Candy Clay maps two families onto the stock M3 type scale in `ui/theme/Type.kt`; **all sp lives inside `Typography()`**, never inline. Phase 9 introduces **no new type role and no new size** — it reuses four roles already in service.

| Role | M3 token | Size | Family / Weight | Line Height | Phase-9 usage |
|------|----------|------|-----------------|-------------|---------------|
| Heading | `headlineSmall` | 24sp | Fredoka **Medium 500** | 32sp (1.33) | Opt-in dialog title (matches the `restart_confirm_title` precedent) |
| Title | `titleMedium` | 16sp | Fredoka **Medium 500** | 24sp (1.50) | Settings privacy-row label |
| Body | `bodyMedium` | 14sp | Nunito **Regular 400** | 20sp (1.43) | Dialog body copy, Settings supporting line, snackbar message |
| Label | `labelLarge` | 14sp | Nunito **Bold 700** | 20sp (1.43) | Dialog action buttons; Settings section headers |

**Size count: 3 (24 / 16 / 14sp).** **Weight count: 3 across two families** — Fredoka Medium 500 for every heading/title, Nunito Regular 400 for every body string, Nunito Bold 700 for every button/label string. This is the shipped system-wide contract (`docs/ui/DESIGN-SYSTEM.md` §Typography: Fredoka 500–600, Nunito 400–700), unchanged by this phase; Phase 9 adds no fourth weight and touches no `Typography()` entry.

Body line-height 1.43 and heading line-height 1.33 are the M3 baseline, accepted as-is (within the ≥1.2 heading / ~1.5 body targets). Tabular figures (`withTabularFigures()`) are **not** used on any Phase-9 surface — no ticking digit appears on the dialog, snackbar or privacy rows.

## Color

M3 roles + the Candy Clay gradient palette only (zero hex in code — every literal lives in `ui/theme/Color.kt`).

| Role | Token | Light / Dark | Usage |
|------|-------|--------------|-------|
| Dominant (60%) | `background` | #F4F1FA / #1B1626 | The gameplay screen behind the dialog scrim; the Settings screen background |
| Secondary (30%) | `surfaceContainerHigh` | #F1EAFB / #2E2740 | The opt-in dialog surface; both Settings privacy row cards |
| Secondary (30%) | `surfaceContainerHighest` | #ECE4F8 / #362E4B | The clay snackbar container (D-11) |
| Accent (10%) | `CtaGradient` (`ctaGradientBrush()`, #A78BFA → #7C3AED) | light/dark variants | **"Watch ad" confirm button only** |
| Reward accent (≤10%) | `GoldGradient` (`goldGradientFill()`, #FDE68A → #F59E0B) | light/dark variants | **The opt-in dialog's reward glyph only** |
| Destructive | `error` / `errorContainer` | #DC2626 / #F87171 | **Not used this phase** |

**Accent reserved-for (explicit and exclusive — never "all interactive elements"):**

- **`CtaGradient`** → the **"Watch ad"** button in `AdOfferDialog`, and nothing else added this phase. This continues the app's single established meaning for the CTA gradient: *the one forward-committing action on this surface* (`restart_board`, `onboarding_got_it`, Results' primary action). "No thanks" is a plain `TextButton` with no gradient — a decline must never compete with the accept.
- **`GoldGradient`** → the decorative reward glyph at the top of `AdOfferDialog`, and nothing else added this phase. `docs/ui/DESIGN-SYSTEM.md` reserves tertiary/gold for **hint & reward semantics** (hints, stars, "New best!"); a rewarded-ad offer whose payload is *more hints/undos* is squarely inside that reservation, which is why it is the right accent here and would be wrong anywhere else in this phase.
- **Neither accent appears on the Settings privacy rows.** They are plain clay cards (`surfaceContainerHigh` + `onSurface` label + `onSurfaceVariant` supporting line), exact peers of the existing Sound and Haptics rows. A privacy-policy link is not a celebration.

**Destructive:** Phase 9 introduces **no destructive action**. Declining the offer changes nothing (D-06: "declining leaves the game exactly as it was"). Watching an ad only ever adds allowance. Changing privacy choices is reversible by re-opening the same form. The `error` role is therefore not used, and no confirmation dialog is added — introducing one would contradict D-06's "one dialog, no second offer surface".

**Contrast:** `onPrimary` (#FFFFFF) on the CTA gradient is already ≥4.5:1 by construction — `ctaGradientBrush()` weights the dark stop to the midpoint (`CTA_DARK_STOP = 0.5f`) precisely so the label sits on the high-contrast half. Snackbar `onSurface` on `surfaceContainerHighest` and row `onSurfaceVariant` on `surfaceContainerHigh` are within the palette's verified ≥4.5:1 body-text pairs in both modes. The gold glyph carries **no text and no unique meaning** (title + body state everything) so it is exempt as decorative.

## Copywriting Contract

All copy lives in `strings.xml`. The two allowance numbers are **formatted from `AssistAllowanceLimits`** (`%1$d`), never typed into the string — so D-02's 3/5 is named exactly once and the copy cannot drift from the policy.

| Element | Copy | String key (proposed) |
|---------|------|------------------------|
| **Primary CTA (this phase)** | "Watch ad" | `ad_offer_watch` |
| Decline action | "No thanks" | `ad_offer_decline` |
| Dialog title — hint | "Out of free hints" | `ad_offer_hint_title` |
| Dialog title — undo | "Out of free undos" | `ad_offer_undo_title` |
| Dialog body — hint (D-07) | "You've used your %1$d free hints for this level. Watch a short ad for %1$d more?" | `ad_offer_hint_body` |
| Dialog body — undo (D-07) | "You've used your %1$d free undos for this level. Watch a short ad for %1$d more?" | `ad_offer_undo_body` |
| Loading state (D-10) | "Loading ad" (spinner `contentDescription`; no visible label) | `ad_offer_loading` |
| Ad-unavailable snackbar — hint (D-11) | "Ad unavailable — hints refilled for free" | `ad_unavailable_hints` |
| Ad-unavailable snackbar — undo (D-11) | "Ad unavailable — undos refilled for free" | `ad_unavailable_undos` |
| Settings section header (existing group) | "General" | `settings_section_general` |
| Settings section header (new group, D-14) | "Privacy" | `settings_section_privacy` |
| Privacy policy row label (REL-05) | "Privacy policy" | `settings_privacy_policy_label` |
| Privacy policy row supporting | "Opens in your browser" | `settings_privacy_policy_supporting` |
| Privacy policy row failure | "Couldn't open the privacy policy — no browser app found." | `settings_privacy_policy_error` |
| Manage-choices row label (CONS-03) | "Manage privacy choices" | `settings_privacy_choices_label` |
| Manage-choices row supporting | "Change your ad consent choices" | `settings_privacy_choices_supporting` |

**Copy rationale (D-05/D-07 — the dialog is the *only* signal the allowance system exists):** the two-sentence body carries count, scope and reward in one breath, exactly the pattern CONTEXT §Specific Ideas names as "the dialog copy pattern that carries the whole system's legibility". The word **"short"** sets the ad's duration expectation; **"for this level"** scopes the allowance so the player does not read it as a global paywall; the title states the fact plainly before the body proposes the trade. The title is deliberately *not* phrased as a question — the question belongs to the body, where the reward is already named (ADS-01 requires the reward be named before an ad can play).

**Empty state:** this phase has no data-list surface. Its analog is **"the free allowance is spent"** — and that state is never blank: it is either the opt-in dialog (ads offerable) or, per D-12, *nothing at all* (the assist simply lands free). There is no screen on which a player sees an empty container, so no empty-state heading/body is specified. Deliberate absence, not an omission.

**Error state (problem + solution path):**
- **Ad can't load or fill (ADS-03/D-11):** the assist lands **first**, then a transient snackbar states the problem and its already-applied resolution — *"Ad unavailable — hints refilled for free"*. No action is offered because none is needed; the em-dash "problem — resolution" shape matches the shipped `nowin_message` ("No winning move — undo or restart").
- **Ads knowably unservable (CONS-04/D-12):** **no error copy at all.** No dialog, no snackbar; assists silently stay free past the allowance, byte-identical to v1.0 behaviour. Surfacing a consent/SDK failure to a puzzle player is noise about a system they were never told existed.
- **No browser to open the policy (REL-05 hardening):** `startActivity` is wrapped in `runCatching`; on `ActivityNotFoundException` the Settings screen shows the same clay snackbar with *"Couldn't open the privacy policy — no browser app found."* — phrased on the shipped `challenge_load_error` ("Couldn't load this level. Tap Retry.") pattern. A tap that does nothing would be a dead end, which the phase's governing sentence forbids.

**Destructive confirmation:** none — no destructive action is introduced (see §Color). "No thanks" is non-destructive and takes no confirmation.

## Interaction Contract — New Surfaces (Phase 9)

All four surfaces are **stateless leaves** with hoisted state and handlers (compose-skill / CLAUDE.md state hoisting). No composable below owns state or logic.

### 1. `AdOfferDialog.kt` — the themed opt-in dialog (ADS-01, D-06/D-07/D-10)

**Host:** `androidx.compose.ui.window.Dialog`, **not** `AlertDialog` (D-06 rules out the stock component that `RestartConfirmDialog` uses). Set `DialogProperties(usePlatformDefaultWidth = false)` so the clay surface controls its own width. It is modal — the board is inert behind the scrim, which is what makes "declining leaves the game exactly as it was" literally true.

**Structure (top → bottom), following the shipped `OnboardingOverlay` composition:**

| Element | Spec |
|---------|------|
| Surface | `shape = MaterialTheme.shapes.extraLarge` (32dp — dialogs use extraLarge per DESIGN-SYSTEM §Shape), `color = surfaceContainerHigh`, `.clayShadow(elevation_dialog, shapes.extraLarge)`, `.padding(horizontal = spacing_lg)`, `.fillMaxWidth().widthIn(max = content_max_width)` |
| Content column | `.padding(spacing_lg)`, `verticalArrangement = Arrangement.spacedBy(spacing_md)`, `horizontalAlignment = CenterHorizontally` |
| Reward glyph | `Icon(Icons.Rounded.PlayArrow, contentDescription = null)` sized `ad_offer_glyph_size` (48dp) with `Modifier.goldGradientFill()`. **Decorative** — null description; the title and body carry all meaning. `PlayArrow` is in `material-icons-core` [VERIFIED: core jar contents] and reads as "a video will play". |
| Title | `headlineSmall`, `onSurface`, centered. `ad_offer_hint_title` / `ad_offer_undo_title` selected by the pending `AdReason`. |
| Body | `bodyMedium`, `onSurfaceVariant`, centered. `ad_offer_hint_body` / `ad_offer_undo_body`, formatted with `AssistAllowanceLimits.FREE_HINTS` / `FREE_UNDOS`. |
| Accept button | `Button`, `shape = MaterialTheme.shapes.medium` (20dp), `ButtonDefaults.buttonColors(containerColor = Color.Transparent, contentColor = onPrimary)`, `Modifier.claySquish().background(brush = ctaGradientBrush(), shape).fillMaxWidth()`. Label `ad_offer_watch` in `labelLarge`. |
| Decline button | `TextButton`, `shape = MaterialTheme.shapes.medium`, `Modifier.claySquish().fillMaxWidth()`, directly beneath the accept button (gap `spacing_sm`). Label `ad_offer_decline` in `labelLarge`. |

**Stacked full-width actions, not a side-by-side row** — because the accept button's content swaps to a spinner (below), a row would reflow mid-interaction, and stacking makes the accept/decline hierarchy unmissable. This matches `OnboardingOverlay`'s shipped two-action stack.

**Sound (Phase 7 D-09/D-11 precedent):** accept = `withClickSound(SoundCue.ButtonForward, onAccept)`; decline = `withClickSound(SoundCue.ButtonDismiss, onDismiss)`. Attached **per callsite**, never to `Modifier.claySquish()`. This is the second dialog in the app where both cues meet — the same rule `RestartConfirmDialog` documents.

**Loading state (D-10, `adOfferLoading == true`):**
- The accept button's `Text` is replaced by `CircularProgressIndicator` sized `ad_offer_progress_size` (24dp), `color = onPrimary`; the button is `enabled = false` and carries `contentDescription = ad_offer_loading`.
- The decline button is **also disabled**, and the dialog becomes non-dismissible (`dismissOnBackPress = false, dismissOnClickOutside = false`). Rationale: `requestRewarded` is already in flight, and a dismissal race between the player and a returning `Granted` is a correctness hazard, not a UX nicety. The wait is hard-bounded by the ~5s `AdConstants.ACCEPT_WAIT_MS` cap, so this can never dead-end.
- The spinner is a **functional** indicator, not decoration — it runs regardless of the OS animator duration scale.

**Dismissal semantics:** scrim tap, system back and "No thanks" are all the same event (`onDismissAdOffer`) while not loading. The dialog leaves; nothing is charged; the game is untouched. Re-tapping the same control simply re-opens it (CONTEXT: no cooldown).

**Test tag:** `AD_OFFER_DIALOG_TEST_TAG = "ad_offer_dialog"` on the clay `Surface`, following `NOWIN_BANNER_TEST_TAG` / `GAME_STATE_TEST_TAG`.

### 2. Clay snackbar on `GameScreen` (ADS-03/D-11)

`GameScreen`'s `Scaffold` gains a `snackbarHost`. **No `SnackbarHost` exists anywhere in the app today**, so the styling is defined here rather than inherited:

```
SnackbarHost(hostState) { data ->
    Snackbar(
        snackbarData = data,
        shape = MaterialTheme.shapes.medium,
        containerColor = MaterialTheme.colorScheme.surfaceContainerHighest,
        contentColor = MaterialTheme.colorScheme.onSurface,
        modifier = Modifier
            .padding(spacing_md)
            .clayShadow(elevation_card, MaterialTheme.shapes.medium),
    )
}
```

The stock M3 snackbar defaults to `inverseSurface` — a dark slab that is foreign to the candy palette and to the "never pure-white/gray, never low energy" anti-pattern list. The clay treatment above is mandatory, not optional. Message text renders in `bodyMedium`. **No action label** — the resolution has already happened. `SnackbarDuration.Short`. Driven by the established `Int`-tick idiom (`adMessage` + `adMessageTick`, mirroring `undoTick`/`selectionTick`/`rejectedTapTick`).

### 3. Settings Privacy section (CONS-03, REL-05, D-14/D-15)

The Settings column gains **two section headers and two new rows**, in this order:

| Order | Element | Spec |
|-------|---------|------|
| 0 | Header "General" | `labelLarge`, `onSurfaceVariant`, `.padding(horizontal = spacing_sm)` |
| 1 | Sound row | existing `SettingsToggleRow`, unchanged |
| 2 | Haptics row | existing `SettingsToggleRow`, unchanged |
| 3 | Header "Privacy" | same style as "General" |
| 4 | Privacy policy row | **always present** (REL-05) |
| 5 | Manage privacy choices row | **rendered only when `state.privacyOptionsRequired`** (CONS-03) |

**The "General" header is added deliberately.** D-14 asks for a *Privacy section*; a section label that appears over one group and not the other is exactly the visual inconsistency this contract exists to prevent. Both headers or neither — and named groups are the honest choice once the screen holds two unrelated concerns. `labelLarge` + `onSurfaceVariant` is the app's shipped caption style (`ResultsScreen`'s `Metric` label).

**`SettingsLinkRow` (new stateless leaf, peer of `SettingsToggleRow`):** identical clay `Card` — `shapes.large`, `surfaceContainerHigh`, `.clayEntrance(order).clayShadow(elevation_card, shapes.large).fillMaxWidth().heightIn(min = settings_row_min_height)` — with `.padding(spacing_md)`, label `titleMedium`/`onSurface` over supporting `bodyMedium`/`onSurfaceVariant` (gap `spacing_xs`), the whole card `clickable` + `.claySquish()`. It differs from the toggle row in exactly one way: a **trailing icon slot instead of a `Switch`**.

- **Privacy policy row:** trailing `Icon(Icons.AutoMirrored.Rounded.ExitToApp, contentDescription = null)` sized `settings_row_icon_size` (24dp), tint `onSurfaceVariant`. In `material-icons-core` and auto-mirrored [VERIFIED: core jar contents]. It is **functional signposting** — this row leaves the app — and it is why the supporting line can stay short. Tapping fires `Intent(ACTION_VIEW, PrivacyLinks.POLICY_URL.toUri()).addFlags(FLAG_ACTIVITY_NEW_TASK)` from `LocalContext.current`, wrapped in `runCatching`; on failure, the Settings snackbar.
- **Manage privacy choices row:** **no trailing icon.** The UMP form opens in-app, so the absence of the glyph is the differentiator — the two rows are honestly distinguishable at a glance, not merely by their labels.

`SettingsScreen`'s `Scaffold` gains the same clay `snackbarHost` defined in §2 (extract the host into one shared composable rather than duplicating the styling).

Entrance stagger orders shift from `SOUND_ROW_ORDER = 0 / HAPTICS_ROW_ORDER = 1` to the 0–5 ordering in the table above, so the `clayEntrance` cascade still reads strictly top-to-bottom.

### 4. Rescue banner — **no visual change** (ADS-04/D-08)

`NoWinBanner.kt` is **not modified**. Its Undo action keeps its current appearance, position, copy (`undo_action`) and handler. When undos remain it spends one, free and instant, exactly as today; at zero — and only when ads are offerable — the same `onUndo` funnel raises the same `AdOfferDialog`. **One consistent allowance, one dialog, no second offer surface.** Any plan task that adds an ad affordance, badge, or alternate label to this banner is out of contract. (This also honours the deferred "should Stuck finishes reach Results" decision by leaving the banner structurally untouched.)

## Deliberate Non-UI (negative contract)

These are load-bearing absences. An auditor finding any of them *implemented* has found a regression, not an improvement.

| Rule | Source | What must NOT exist |
|------|--------|---------------------|
| Hint and Undo controls never change appearance | D-05 | No counter badge, no "×3" chip, no ad icon, no tint change, no disabled state driven by the allowance. `HintControl.kt` / `UndoControl.kt` / `HintToggleControl.kt` are untouched. |
| No allowance count in `GameUiState` | D-05 + Phase 7 precedent | The counters stay in the ViewModel's private state and the resume snapshot. A value the UI must not act on does not enter the UiState. |
| No first-run explainer | D-07 | No intro snackbar, no update-day changelog dialog, no tooltip. The dialog copy is the whole explanation. |
| No UI when ads are unservable | D-12 | No dialog, no snackbar, no banner, no "ads unavailable" indicator anywhere. v1.0 parity, exactly. |
| No clock UI change | ADSF-01 | The freeze is invisible: the timer simply does not advance. No "paused" chip, no dimmed timer, no resume animation. |
| No second offer surface | D-08 | No ad affordance on the rescue banner, the top bar, Results, or Home. |
| No consent UI authored by the app | CONS-01/CONS-03 | The consent form and the privacy-options form are UMP-rendered. The app authors only the two Settings rows that *reach* them. |

## Animation & Motion

Phase 9 adds **no new motion timing token**. Every animation below is already shipped in `ui/theme/Clay.kt` / `ClayAnim.kt`.

| Surface | Motion |
|---------|--------|
| Dialog action buttons | `Modifier.claySquish()` — scale to `ClayAnim.PRESSED_SCALE` on press, MediumBouncy spring release. Self-gates to a no-op when the OS animator scale is 0. |
| Settings privacy rows | `Modifier.clayEntrance(order)` — the existing 40ms/item fade+slide-up stagger, distance `entrance_slide_distance`. Same gate. |
| Dialog enter/exit | Compose `Dialog` default (platform window transition). No custom spec — a bespoke enter here would compete with the reward glyph for attention. |
| Loading spinner | M3 `CircularProgressIndicator` default indeterminate motion. **Functional**, so it runs even when decorative motion is disabled. |
| Snackbar | M3 default enter/exit. |
| Reward glyph | Static. No pulse, no shimmer — the gold gradient is already the celebratory signal, and an animated glyph on a monetization prompt reads as pressure. |

## Accessibility

- **Dialog:** title + body are read in order; the reward glyph is `contentDescription = null` (decorative, meaning fully duplicated in text). While loading, the accept button announces `ad_offer_loading` ("Loading ad") and is `enabled = false` so TalkBack reports it as disabled.
- **Touch targets:** M3 `Button`/`TextButton` apply `minimumInteractiveComponentSize()` (48dp) automatically, and both dialog actions are `fillMaxWidth()`. The Settings link rows are ≥72dp via `settings_row_min_height`, tappable across the whole card — no icon-sized tap target is introduced.
- **Settings rows:** the trailing `ExitToApp` glyph is decorative (`contentDescription = null`); "Opens in your browser" carries that information as text, so the destination is never conveyed by icon alone.
- **Contrast:** every text pair is drawn from the palette's verified ≥4.5:1 set in both light and dark (see §Color).
- **Color is never the only channel:** the accept/decline distinction is carried by position (accept above), fill (gradient vs. flat) and label — not by hue alone.
