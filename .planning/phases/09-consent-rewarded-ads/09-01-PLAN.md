<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| stored snapshot blob → `SnapshotMapper.decode` | The persisted resume row is untrusted input: it is a JSON blob on device storage that a rooted or backup-editing player can rewrite |
| `:domain` ← app modules | The allowance policy must remain reachable only as pure Kotlin; an Android import here would silently make it untestable and unauditable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | `ResumeSnapshotDto.freeHintsRemaining` / `freeUndosRemaining` | mitigate | `AssistAllowance.fromStoredOrFull` accepts a stored value only when `it in 0..limit`; anything else falls open to the **default** allowance, never to the stored value. ASVS V5. Asserted by the `9999` test case. |
| T-09-02 | Denial of service (self-inflicted) | `SnapshotMapper.fromDto` | mitigate | A forged counter must NOT refuse the snapshot (the `minimumPegs` reject path). Rejecting would convert a tamper attempt into progress loss for an honest player whose blob was corrupted by an unrelated bug. Asserted by the non-null-RestoredGame half of the same test. |
| T-09-03 | Tampering (integer) | `AssistAllowance.spend` | mitigate | `coerceAtLeast(0)` makes `spend` total for every `Int`, so no caller sequence can produce a negative counter that later reads as "infinite free assists" through a signed comparison. |
| T-09-04 | Elevation of privilege (architecture erosion) | `:domain` package purity | mitigate | `DomainPurityTest` forbids `android..`/`androidx..` in `:domain`; run it as part of this plan's verify, not only at phase end. |
