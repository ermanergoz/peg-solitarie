GMA Next-Gen API surface, verified against the official Kotlin reference (RESEARCH.md §Pattern 7 and
§Sources). **Almost every rewarded-ads tutorial online covers the legacy `com.google.android.gms.ads`
API and will not compile here:**
- `com.google.android.libraries.ads.mobile.sdk.rewarded.RewardedAd` is an **interface** whose companion
  exposes `suspend fun load(adRequest: AdRequest): AdLoadResult<RewardedAd>` alongside a callback form
- `AdLoadResult` is `sealed interface AdLoadResult<AdT : Ad>` in `…sdk.common` with `Success` and `Failure`
- the ad unit ID belongs to the **request**: `AdRequest.Builder(adUnitId)`; `AdRequest.adUnitId` is required
- `fun show(activity: Activity, onUserEarnedRewardListener: OnUserEarnedRewardListener)`; the SAM is
  `fun onUserEarnedReward(reward: RewardItem)`
- `var adEventCallback: RewardedAdEventCallback?`, which inherits `onAdShowedFullScreenContent()`,
  `onAdDismissedFullScreenContent()`, `onAdFailedToShowFullScreenContent(FullScreenContentError)`,
  `onAdImpression()`, `onAdClicked()`, `onAdPaid(AdValue)`
- `Ad.destroy()` exists and should be called on a slot being discarded
- `MobileAds.isInitialized` is a volatile boolean

Assumption to confirm at compile time (RESEARCH A3): `AdLoadResult.Success` exposes the ad as `.ad`.
If the property name differs, take it from the IDE/compiler — this is a 30-second discovery with zero
design risk, not a reason to change the shape.

  <action>
    Create `RewardedAdSlot` as a `@Singleton class RewardedAdSlot @Inject constructor(...)` holding at
    most **one** loaded `RewardedAd` plus the wall-clock instant it was loaded. Surface:
    - `fun preload(reason: AdReason)` — fire-and-forget; launches a load on the injected scope if the
      slot is empty and no load is already in flight. Idempotent.
    - `suspend fun await(reason: AdReason): RewardedAd?` — returns the held ad immediately if present
      and not over-age, otherwise triggers a load and suspends until it completes or the caller's
      timeout fires. The **caller** applies `AdConstants.ACCEPT_WAIT_MS`; do not bury a second timeout
      here, or the D-10 bound becomes two bounds that can disagree.
    - `fun invalidate()` — calls `destroy()` on the held ad and empties the slot.

    Load with the coroutine-native companion:
    `when (val result = RewardedAd.load(AdRequest.Builder(AdIds.rewardedAdUnitId).build())) { is AdLoadResult.Success -> result.ad; is AdLoadResult.Failure -> null }`.
    A `Failure` (no fill, network error) is not an exception path — it becomes `null`, which the
    gateway maps to `RewardOutcome.Unavailable`, which grants the assist anyway (ADS-03).

    Retry: **one bounded retry at most**, using the `AdConstants` cadence value. Do not write an
    exponential backoff loop: an unbounded retry against a no-fill condition burns battery and can look
    like abusive traffic. If managed retry is ever wanted, the SDK's own `RewardedAdPreloader` is the
    answer — but it keeps refilling its buffer for the rest of the session after each `pollAd()`, which
    fights D-09's "no ad requests while allowance remains" and would force a `destroy(preloadId)` after
    every refill. Record that trade-off in the class KDoc so the choice is legible.

    Treat a slot older than the ad-expiry cadence constant as **empty** and reload rather than showing
    it. Rewarded ads are single-show and legacy documentation puts expiry at roughly one hour; that
    figure is `[ASSUMED]` for Next-Gen (RESEARCH A1), so mark the constant's KDoc as a defensive bound
    rather than a documented guarantee. The real safety net is
    `onAdFailedToShowFullScreenContent` → `Unavailable`, which covers it regardless.

    Every SDK type stays inside this file and `AdMobAdGateway`; nothing here is exposed outside
    `..platform..`.
  </action>

  <action>
    Create `AdMobAdGateway` as a `@Singleton class AdMobAdGateway @Inject constructor(...)`
    implementing `AdGateway`, taking the `ConsentGateway`, the `RewardedAdSlot`, the
    `ForegroundActivityProvider` and an `@ApplicationScope CoroutineScope`.

    `rewardedOfferable`: a `StateFlow<Boolean>` derived from `consentGateway.readiness` — `true` only
    for `AdsReadiness.Ready`. `Unknown` maps to **false**, not "offerable, let's find out": a fast
    player on a slow network can exhaust an allowance before bootstrap completes, and showing a dialog
    then discovering the SDK is uninitialized produces exactly the "watch an ad? → instant free grant"
    absurdity D-12 rules out (Pitfall 16). Expose it with `asStateFlow()` or a `map(...).stateIn(scope, …)`
    — never leak a mutable flow.

    `preloadRewarded(reason)`: delegate to `slot.preload(reason)` only when `rewardedOfferable.value`
    is true. D-09 means no request while allowance remains; there is nothing to gain from loading an
    ad the consent state forbids serving.

    `requestRewarded(reason)`, following RESEARCH Pattern 7 exactly:
    1. `if (consentGateway.readiness.value != AdsReadiness.Ready) return RewardOutcome.Unavailable` —
       the SDK-side half of the CONS-02 gate.
    2. `val ad = withTimeoutOrNull(AdConstants.ACCEPT_WAIT_MS) { slot.await(reason) } ?: return RewardOutcome.Unavailable`
       — D-10's bounded wait, the one the dialog's spinner is showing.
    3. `val activity = withTimeoutOrNull(AdConstants.ACTIVITY_WAIT_MS) { activityProvider.awaitActivity() } ?: return RewardOutcome.Unavailable`.
       Capture the Activity **before** `show()` and never re-await one inside a callback:
       `ForegroundActivityProvider.current` is deliberately null while a fullscreen ad is on screen
       because showing an ad pauses the host, and the failure mode of re-awaiting is a hang, not a
       crash (Pitfall 13).
    4. `suspendCancellableCoroutine { cont -> … }` with a local `var earned = false`. Assign
       `ad.adEventCallback = object : RewardedAdEventCallback { … }` overriding
       `onAdDismissedFullScreenContent()` — `slot.invalidate(); slot.preload(reason)`, then resume with
       `Granted` if `earned` else `Declined` — and `onAdFailedToShowFullScreenContent(error)` —
       `slot.invalidate(); slot.preload(reason)`, resume `Unavailable`. Guard both resumes on
       `cont.isActive`. Then `ad.show(activity) { _: RewardItem -> earned = true }` and
       `cont.invokeOnCancellation { ad.adEventCallback = null }`.

    **`earned = true` appears in exactly one place in the codebase: inside the
    `OnUserEarnedRewardListener` passed to `show()`.** Never set it in
    `onAdDismissedFullScreenContent`, and never infer it from a dismissal. ADS-05 and the AdMob
    rewarded-inventory policy both require the reward come only from that callback; granting on
    dismissal is fraud against the advertiser and is the single most consequential line in this plan.

    `showInterstitial()` stays a no-op with a KDoc saying Phase 10 owns it. Do not implement
    interstitials here.

    Threading: `MobileAds.initialize` runs on a background dispatcher inside `UmpConsentGateway`
    (plan 09-05); **every other GMA call must be on the main thread**. `requestRewarded` is called
    from `viewModelScope`, which is main by default — keep it there and do not add a `withContext(IO)`.
    Say so in the KDoc, because adding one would look like an improvement.

    Log nothing about ad response info or consent status in release (ASVS V7).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app ↔ AdMob ad-serving network | The first time this app makes an outbound request tied to an advertising identifier; consent state governs whether it may happen at all |
| ad SDK callbacks ↔ reward economy | The SDK decides whether a reward was earned; the app must not second-guess it in either direction |
| foreground Activity lifetime ↔ fullscreen ad | The host Activity is paused for the whole ad, so any code awaiting it during the ad hangs |
| debug/CI builds ↔ real ad inventory | Real ad unit IDs reaching a dev build produce invalid traffic and risk the AdMob account |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
