| Boundary | Description |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-09 | Repudiation (policy violation → account loss) | `AdOfferDialog` accept/decline hierarchy | mitigate | AdMob policy: "cannot include any text or icons, other than to describe the reward(s) offered, to mislead or incentivize users towards a particular choice." Both actions are full-width stacked peers; decline is a real `TextButton`, not a muted micro-link. Asserted by the test that clicks the decline node by its string-resource text. |
| T-09-10 | Repudiation (policy violation) | dialog copy | mitigate | Policy requires "clear, accurate and conspicuous disclosure of the action(s) required and reward(s) offered prior to each instance." The body names the count, the scope ("for this level") and the reward, and is formatted from `AssistAllowanceLimits` so it cannot drift from the policy that grants it. |
| T-09-11 | Tampering (state race) | `loading` state dismissal | mitigate | While loading, both actions are disabled and `dismissOnBackPress`/`dismissOnClickOutside` are false, so no player input can race a returning `Granted` into a state where the reward is granted but the dialog has already been torn down. Bounded by `AdConstants.ACCEPT_WAIT_MS`, so the lock can never dead-end. |
| T-09-12 | Elevation of privilege (architecture erosion) | `ui/game`, `ui/components` | mitigate | Neither new composable names `android.app.Activity` or any SDK type; `PlatformBoundaryTest` remains green. Verified by `./gradlew check --offline`. |
| T-09-SC | Tampering | package-manager installs | accept | No packages installed; no new dependency (UI-SPEC §Registry Safety confirms Phase 9 adds none). Both existing ad artifacts are **Approved** in RESEARCH.md's audit table. |
