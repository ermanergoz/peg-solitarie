<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → external browser via `ACTION_VIEW` | An implicit intent hands control to an arbitrary app; the URI is the whole attack surface |
| UI layer → `android.app.Activity` | `PlatformBoundaryRules.uiAndDomainNeverTouchAnActivity` forbids any `..ui..` class from depending on `Activity`; the UMP form must be reached through the seam instead |
| UMP server configuration → row visibility | Whether a privacy-options entry point is required is server-decided and regionally variable; any client-side inference is both wrong and a compliance exposure |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-27 | Tampering (intent redirection) | `SettingsScreen` `ACTION_VIEW` | mitigate | The URI is `PrivacyLinks.POLICY_URL`, a `const val` compiled into the APK — never read from storage, a navigation argument, or a remote value. ASVS V12. Enforced by the acceptance criterion that the screen references `PrivacyLinks.POLICY_URL` and by the constant's own KDoc. |
| T-09-28 | Denial of service (dead end) | privacy-policy row on a browser-less device | mitigate | `startActivity` is wrapped in `runCatching`; `ActivityNotFoundException` surfaces `settings_privacy_policy_error` in the clay snackbar. Covered by a `<behavior>` test case. |
| T-09-29 | Elevation of privilege (architecture erosion) | Settings → Activity | mitigate | `LocalContext.current` only, with `FLAG_ACTIVITY_NEW_TASK`; `showPrivacyOptions()` takes no Activity and resolves one inside the platform layer. `PlatformBoundaryTest` is in this plan's verify. |
| T-09-30 | Spoofing (compliance) | CONS-03 row visibility | mitigate | Visibility is driven solely by `consentInformation.privacyOptionsRequirementStatus == REQUIRED`, surfaced through `ConsentGateway`. No geo-IP check, no region string, no cached inference — the SDK is the only source of truth. |
| T-09-31 | Information disclosure | policy content vs. app behaviour | transfer | The policy must name advertising-ID collection and every third-party SDK receiving player data, and Phase 14's Data-safety form (REL-01/REL-04) must be written *from* it. Verified as part of the Task 1 human gate; filing is Phase 14's responsibility. |
| T-09-SC | Tampering | package-manager installs | accept | No packages installed. D-15 rules out `androidx.browser` Custom Tabs, so no new dependency enters here. RESEARCH.md's audit table records both phase artifacts as **Approved**. |
</threat_model>
