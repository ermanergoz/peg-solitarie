<objective>
Give the Results celebration its second beat: a rising-pitch star-pop sequence that lands in step
with the stars that are already animating in, plays exactly once per win, and survives the
reduced-motion setting that makes the visual pops instantaneous.

Purpose: SOUND-03's second half. The win stinger already fired on the board (plan 07-03, D-14);
this is the ceremony. Three locked decisions shape it — D-15 makes the pitch ladder a *prefix*, so
the resolving top note is audibly earned only by a 3-star finish; D-13 deliberately breaks the
file's existing "respect the animator-duration-scale gate" symmetry so the audio celebration
survives reduced motion; D-16 makes it once per win, mirroring the `recordSolvedPlayOnce` idiom
that already lives in this ViewModel.

Output: `playCelebration` on `ResultsUiState`, a `SavedStateHandle` latch in `ResultsViewModel`, a
`StarPopSounds` composable in `ResultsCelebration.kt` called from `StarRow`, and two test files.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| route args → Results state | `stars` arrives as a typed navigation argument computed in-game; the celebration reads it to decide how many pops to play. |
| SavedStateHandle → play-once latch | The latch survives process death, so its value is restored state rather than freshly computed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Denial of Service | `SoundParams.starPopRate(step)` | mitigate | `starPopRate` clamps into `[MIN_RATE, MAX_RATE]` (plan 07-02) and `step` is bounded by `earned`, which is itself bounded by `TOTAL_STARS`. `repeat(earned)` cannot iterate negatively. Asserted by the 3-star rate-order test. |
| T-07-10 | Spoofing (state) | `playCelebration` restored from `SavedStateHandle` | accept | The latch is a boolean whose only effect is whether a sound plays. A tampered value can at worst suppress or repeat a celebration sound; it grants nothing and reaches no persistence. The bests merge remains guarded by its own separate `RECORDED_KEY`, which this plan does not touch. |
| T-07-11 | Denial of Service (user-facing) | unbounded pop sequence | mitigate | The sequence is `repeat(earned)` inside a `LaunchedEffect` keyed on `(play, earned)`, cancelled with the composition. It cannot outlive the screen and cannot restart without a key change; the "recomposition does not replay" test asserts this. |
| T-07-06 | Denial of Service (user-facing) | audio after leaving Results | accept | The `LaunchedEffect` is cancelled when the composition leaves. Any pop already handed to `SoundPool` is a sub-second one-shot at media volume; no looping path exists. |
</threat_model>
