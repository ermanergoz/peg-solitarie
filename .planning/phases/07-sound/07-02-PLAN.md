## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| app → OS audio policy service | `SoundPool` writes to `STREAM_MUSIC`. Whether the user's own audio is ducked or interrupted is decided by focus policy, which this component deliberately never engages. |
| UI layer → audio engine | Derived integers (`runIndex`, star `step`) cross into playback-rate arithmetic. In-process and already validated, but unbounded by type. |
| Settings store → audio engine | `soundOn` crosses from DataStore into a process-wide mute gate held by a `@Singleton`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-02 | Denial of Service | `SoundParams.jumpRate` / `starPopRate` | mitigate | Explicit `coerceIn(MIN_RATE, MAX_RATE)` makes both functions total for any `Int` including negatives (ASVS V5). Asserted directly by `SoundParamsTest` for indices -1, 12 and 50, so the clamp is a tested contract rather than a reliance on the engine's silent clamp. |
| T-07-03 | Denial of Service | `SoundPoolPlayer.activeStreams` under rapid tapping | mitigate | `setMaxStreams(SoundParams.MAX_STREAMS = 8)` lets SoundPool voice-steal by priority then age; the tracked-id `ArrayDeque` is bounded to the same size and evicts oldest on push. `SoundPoolPlayerTest` asserts the collection never exceeds `MAX_STREAMS` after 100 rapid plays. |
| T-07-04 | Denial of Service (user-facing) | `SoundPoolPlayer` construction | mitigate | No `AudioManager` is obtained and `requestAudioFocus`/`abandonAudioFocusRequest` are never called. Enforced permanently by `audioFocusLiteralCheck` (plan 07-01) and asserted structurally by the acceptance criteria on Task 2. |
| T-07-05 | Elevation of Privilege | Hilt binding scope | mitigate | `@Singleton` is placed on the `SoundPoolPlayer` class as well as the `@Binds`. `@Binds @Singleton` scopes the binding of the interface, not the concrete class, so without the class-level annotation any injection of the concrete type would create a second unscoped instance owning a second `SoundPool` — and the SOUND-05 mute would reach only one of them. |
| T-07-06 | Denial of Service (user-facing) | background playback | accept | No background playback path is created: every cue is fired from a `LaunchedEffect` inside a composition, which stops with the composition. The player exposes no looping or scheduled playback API. Documented so nobody adds one. |
| T-07-07 | Information Disclosure | network egress | accept | The phase adds no runtime network path. Assets are compiled into the APK; no `INTERNET`-dependent code is introduced and no new permission is required to play to `STREAM_MUSIC`. |
