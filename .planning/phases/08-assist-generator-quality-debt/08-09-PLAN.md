<objective>
Make the committed book readable from production code, with a lookup that distinguishes a miss from
an authoritative answer.

RESEARCH's PATTERNS map flags this as one of only three places in the phase where NO analog exists:
there are **zero** occurrences of `getResourceAsStream`, `getResource` or `javaClass.classLoader`
anywhere in `app/src` or `domain/src`. Every existing fixture read is
`java.io.File("src/test/resources/golden/...")` — a relative path that only resolves because Gradle
sets the test working directory to the module root, and which cannot work in a shipped APK.
`domain/src/main/resources/` did not exist before plan 08-08. This is a genuinely new mechanism and
gets its own plan.

The correctness rule that matters most, from RESEARCH Pattern 2: **a book miss must fall through to
the solver; a book hit recording "no winning move" is authoritative.** Conflating the two would
reintroduce the exact untruthfulness DEBT-01 exists to remove. The API therefore has three outcomes,
not two.

Purpose: give the hint pipeline (plan 08-10) something to call, with an integrity contract strong
enough that a book hit can be trusted.
Output: `OpeningBook` and `OpeningBookTest`.
</objective>

Create `domain/src/main/kotlin/com/app/pegsolitaire/domain/assist/OpeningBook.kt` in package
`com.app.pegsolitaire.domain.assist`.

Declare the `BookAnswer` sealed interface with `Hit` and `NoWinningMove` exactly as in the
`<interfaces>` block, and KDoc the three-outcome contract on `lookup` in the strongest terms
available: `null` means the book does not know and the caller MUST consult the solver;
`NoWinningMove` means the position was proven at authoring time to have no winning line and is
authoritative; collapsing the two is the correctness bug this whole requirement exists to remove.

Build a private `BOOK_RESOURCE_NAMES: Map<List<Position>, String>` from explicit
`Boards.<Spec>.footprint to "<name>"` pairs for the five boards, using the same slugs the committed
files carry (`english33`, `european37`, `asymmetric39`, `diamond41`, `wiegleb45`). Keying on
`footprint` rather than on the `BoardSpec` instance is what lets a spec rebuilt from a resume blob
find its book — KDoc that reason, because referential identity would look correct in every normal
test and fail only on resume.

Load each board's file lazily and at most once, from `/golden/book/{name}-k4.txt` via
`OpeningBook::class.java.getResourceAsStream(...)` with an ABSOLUTE (leading-slash) path. Keep the
per-board loaded state in a map from resource name to a loaded result, including a memoised FAILURE
state so a missing or corrupt resource is not re-read on every hint. Guard the map with
`@Synchronized` or an equivalent lock — no coroutine primitives cross into `:domain`.

Parse fail-closed, per RESEARCH §Security Domain: skip blank lines and lines beginning with `#`;
decode every other line with `OpeningBookFormat.decodeEntry`; if ANY line fails to decode, or the
resource is absent, or the stream throws, mark that board's book UNAVAILABLE and return `null` from
every subsequent lookup for it. Never serve a partially-parsed book. Catch `IOException` explicitly
rather than blanket-catching `Exception`, and let `decodeEntry`'s `null` return carry malformed-line
detection.

`lookup(board)` resolves `BOOK_RESOURCE_NAMES[board.spec.footprint]`, loads that board's entry map,
and returns `Hit(move)` / `NoWinningMove` / `null` according to whether `board.pegs` is present and
whether its recorded move is non-null. Do NOT re-validate the move against `RulesEngine` here — that
guard belongs at the hint boundary (plan 08-10, threat T-04-CT) where it also covers the recorded-line
path, and duplicating it would put the same check in two places with two chances to drift. State that
delegation explicitly in the KDoc so it is a decision, not an omission.

Add a KDoc note recording assumption A5: `:domain` is a plain JVM module so `getResourceAsStream`
works, but Phase 6 introduced R8 and resource shrinking for the first time; plan 08-11 proves the
resources survive into the release APK, and if they ever do not, the documented escape hatch is to
move the book to Kotlin string constants.

Every parse constant (resource directory, suffix, comment prefix) is a KDoc'd private const —
CLAUDE.md's no-magic-strings rule.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| classpath resource → hint answer | The book is read from the app's own JAR, so it is not user-supplied; but a truncated or R8-mangled resource is still untrusted input and must fail closed. |
| book answer → player-visible move | A book entry that is stale or illegal on the current board would make the hint highlight a move gameplay rejects. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-30 | Tampering | Truncated or corrupt book resource parsed into partial entries | mitigate | Any malformed line makes the whole board's book unavailable and every lookup returns `null` (miss), falling through to the solver. Directly tested in Task 3 via an `internal` parse seam with malformed, truncated and missing payloads. |
| T-08-31 | Spoofing (correctness) | A book miss mistaken for an authoritative "no winning move" | mitigate | Three distinct outcomes (`Hit` / `NoWinningMove` / `null`) with the rule stated in the `lookup` KDoc, and Task 3 asserts an out-of-catalog board and a depth-5 position both return `null`. |
| T-08-32 | Tampering | Book entry naming a move that is illegal on the current board | transfer | Deliberately NOT re-validated here — the single `RulesEngine.legalMoves` guard lives at the hint boundary in plan 08-10, where it also covers the recorded-line path (threat T-04-CT). Duplicating it would give the same check two places to drift. Task 2 does assert entry-level legality of the committed data in CI. |
| T-08-33 | Tampering | Referential rather than structural catalog key silently disabling the book after resume | mitigate | The catalog is keyed on `BoardSpec.footprint`, and Task 3's shuffled-footprint test would fail on a referential key. This is Pitfall 3 restated at the book boundary. |

| T-08-SC | Tampering | package-manager installs | n/a | No packages installed (RESEARCH §Package Legitimacy Audit: zero new coordinates). |
