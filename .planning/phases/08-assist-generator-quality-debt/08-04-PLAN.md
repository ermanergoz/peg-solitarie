<objective>
Build the precomputed per-footprint tables the bitboard solver runs on, and generalise the
colour-parity prune to the per-board target.

RESEARCH measured the shipped solver at ~0.27M nodes/s against a tuned bitboard reference at ~15M
nodes/s — a ~55x pure constant factor, entirely attributable to per-node allocation: a `List<Move>`
of data-class objects, a `sortedByDescending` with a fresh `Random.nextDouble()` per move, a `Board`
data-class copy per move, and a `Pagoda` pass that iterates every in-play cell with a
`Math.floorMod` and a lambda call. This plan builds the tables that delete all of it.

It also fixes the thing that makes Diamond-41 hints structurally incapable of telling the truth:
`Pagoda.mayBeSolvable` currently asserts the terminal parity vector has weight exactly 1, so it
returns `false` for EVERY Diamond-41 position and `Solver.firstWinningMove` returns `null` in
O(cells) with zero search. That is why Diamond's hint can only ever say "no winning move".

Purpose: plan 08-05 rewrites `Solver`'s inner loop on top of these tables. Doing both in one plan
would exceed the context budget and mix two distinct correctness arguments.
Output: `SolverTables`, a target-aware `Pagoda`, and property nets under both.
</objective>

New — `domain/src/main/kotlin/.../solver/SolverTables.kt`:
- `internal class SolverTables` with, for a given `BoardSpec`:
  - `needMask: LongArray` — per move index, `bit(from) or bit(over)`; both must hold pegs
  - `toMask: LongArray` — per move index, `bit(to)`; must be empty
  - `xorMask: LongArray` — per move index, `needMask or toMask`; applying the move is ONE xor
  - `moveOrder: IntArray` — move indices pre-sorted by inwardness (descending), computed once
  - `classPlus: LongArray` — 3 masks, bits whose `(row + col) mod 3 == i`
  - `classMinus: LongArray` — 3 masks, bits whose `(row - col) mod 3 == i`
  - `chunkTables: BoardCanonical.ChunkTables` — the canonicalisation tables from plan 08-02
  - `moveAt(index: Int): Move` — the `Move` a move index denotes, for surfacing a result
- `companion object { fun forSpec(spec: BoardSpec): SolverTables }` — bounded-cache memoised

Existing, unchanged — `domain/src/main/kotlin/.../solver/Pagoda.kt` public contract:
- `object Pagoda { fun mayBeSolvable(board: Board): Boolean }`
  One-directional: `false` means provably unreachable; `true` means "not excluded", never a proof.

Existing — `domain/src/main/kotlin/.../rules/RulesEngine.kt`:
- `fun legalMoves(board: Board): List<Move>` and `fun applyMove(board: Board, move: Move): Board`
  These remain the SINGLE move authority; the tables must agree with them, never replace them as
  the definition of legality.

parities of each colouring, and reaching a T-peg terminal from a P-peg position takes exactly `P - T`
