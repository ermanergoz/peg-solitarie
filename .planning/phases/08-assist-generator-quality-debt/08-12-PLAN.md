<objective>
Close the single blocking gap left by Phase 8 verification: the hint system can display a move (or a
"no winning move" banner) that was computed for a board the player has already moved past.

Verification (`08-VERIFICATION.md`, `status: gaps_found`) failed exactly one truth —
**"Every hint the game shows is a legal move on the board the player is actually looking at"** — the
UI-layer half of DEBT-01's "the hint system tells the truth". The domain half is done and proven:
the opening book, the bitboard solver and `GetHintUseCase`'s single legality guard all hold. What is
unclosed is code review finding **CR-01** (`08-REVIEW.md`), confirmed unfixed at HEAD:

- `onHintRequested` launches `hintJob`, which can legitimately run the full 1.5 s deadline (the
  documented off-book Diamond-41 worst case, where the pagoda prune is provably vacuous).
- The board stays fully tappable during the search — `GameScreen` disables only the Hint control.
- Neither `performJump` nor `onUndo` cancels `hintJob`; cancellation exists only in
  `onHintRequested` and `resetToInitial`.
- The result handler applies its outcome unconditionally, and the `withContext(defaultDispatcher)`
  block reads `_uiState.value.board`, `moveHistory.size` and `onRecordedLine` **on the background
  thread**, so the three inputs can even be mutually inconsistent with each other.

The `RulesEngine` tap path still refuses to *play* an illegal move, so game state cannot be
corrupted — but a glow pointing at an empty cell, or a rescue banner on a position that was never
searched, is precisely the "highlighted move gameplay then rejects" failure that `GetHintUseCase`'s
own KDoc names as a visible correctness failure, and that every book and solver test in this phase
asserts can never happen.

Scope is surgical and deliberately narrow. This plan does **not** revisit plans 08-01..08-11, does
not touch `:domain`, and does not address the three accepted overrides (Wiegleb-45 K=3, English-33's
four proven-dead markers, the deferred on-device checklist) — those are developer-approved and
tracked. The two non-blocking warnings from the same review (WR-01 snapshot scope, WR-02 duplicated
cue carry-forward) are out of scope: verification classified them as orthogonal to this phase's
must-haves.

Purpose: make the phase's truthfulness claim airtight end-to-end, not just inside `:domain`.
Output: a cancellation + input-capture + board-identity fix in `GameViewModel`, and a deterministic
JVM spec that fails on the race today and passes once it is closed.
</objective>

| main dispatcher ↔ `defaultDispatcher` | The only boundary this plan crosses. Mutable ViewModel state (`_uiState`, `moveHistory`, `onRecordedLine`) lives on the main thread; the hint search runs on a background dispatcher. Today the background side reads that state directly, with no happens-before edge. |
| player tap ↔ ViewModel | Pre-existing and unchanged: `performJump` re-derives every move from `RulesEngine.legalMoves` and never trusts the tap-asserted destination (T-03-01). |

this section; the two real entries below are integrity-of-displayed-information issues, not
