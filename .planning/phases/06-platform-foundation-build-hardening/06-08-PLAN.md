The number it produces is coarse — record that fact alongside it rather than implying benchmark-grade precision.

**External Prerequisites are the milestone's single biggest schedule risk.** From `.planning/ROADMAP.md` § External Prerequisites and `.planning/STATE.md` § Blockers/Concerns: `app-ads.txt` needs a **developer website** and up to a 24-hour crawl, and no developer website exists yet. Play Console PGS tester propagation takes hours to days. Achievement icons and the UMP consent message both block silently. None of these has a code equivalent and none can be compressed at release time.

Sample cold start 10 times: for each iteration run `adb shell am force-stop com.app.pegsolitaire`, wait ~2 s, then `adb shell am start -W -n com.app.pegsolitaire/.MainActivity`, capturing the `TotalTime` and `WaitTime` values. Discard the first iteration as a warm-up and record the remaining nine.

Add a precision caveat in plain words: `am start -W` displayed-time is coarse, it is affected by device thermal state and background load, and it is not comparable across devices — Phase 14 must re-measure on the **same** device to make PLAT-08 meaningful.
