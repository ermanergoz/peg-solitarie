<objective>
Close security advisory **WARN-02** (D-13): bound the row/col values decoded out of a stored resume snapshot, so a tampered or corrupt blob cannot produce a degenerate off-canvas board.

Purpose: the v1.0 audit's finding was not "the code is wrong" but "this path has no proof". `SnapshotMapper` already validates tuple arity, footprint size, duplicates, target membership and peg-mask width — but never the coordinate *values*. A blob containing `[-5, 3]` or `[1073741824, 0]` passes today.
Output: one guarded decode helper, six regression cases, and committed closure evidence.
</objective>

**The bound is already a named constant — do not invent one.** `ResumeSnapshotFormat.MAX_BOARD_POSITIONS` (= `Long.SIZE_BITS` = 64) exists at `ResumeSnapshotDto.kt:96-100` because a `Board`'s peg mask is a single `Long`. `0 until MAX_BOARD_POSITIONS` (i.e. `0..63`) is the tightest **sound** bound: a 64-cell footprint could in principle be a 1×64 line. A tighter bound such as 9 (the largest current `GRID_DIMENSION`) would be tighter today but would fail-**closed** on a future larger board, silently destroying a player's in-progress game.

**Fail-safe, not fail-fast.** This is the untrusted-input boundary. Reject and return `null`; `SnapshotMapper.decode` already catches and degrades to a fresh board. Never throw. (`SnapshotMapper.kt:113-123` is the philosophy this fix extends.)
</context>
