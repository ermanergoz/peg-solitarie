**Pitfall 9 dictates this plan's shape.** `android.onlyEnableUnitTestForTheTestedBuildType` defaults to `true` in AGP 9.1.0, so **there is no `testReleaseUnitTest`**. A JUnit test in `:app` asserting release-ID behaviour would never run. D-09's release-failure proof must therefore be a **pure function in `build-logic`**, unit-tested there. `build-logic` currently has **no test source set at all**.

**Pitfall 1:** `BuildFeatures.buildConfig` defaults to `false` in AGP 8+/9. Without `buildFeatures { buildConfig = true }`, every `buildConfigField` silently generates nothing and `BuildConfig.REWARDED_AD_UNIT_ID` fails to resolve. Land the flag in the same commit as the fields.

**Pitfall 2:** the third `buildConfigField` argument is a **Java/Kotlin source literal**, not a value. A `String` field needs embedded quotes.

**Pitfall 3 / assumption A3:** AGP configures *every* variant on *every* invocation, so a naive `require(...)` inside `buildTypes.release { }` fires during `assembleDebug` and during IDE sync — breaking D-08. Gate on `gradle.startParameter.taskNames`, which is **empty during IDE sync**, which is exactly the behaviour you want. `androidComponents.onVariants(withBuildType("release"))` does **not** solve this.

**Anti-pattern to resist:** the project's no-magic-strings rule pushes toward an `AdConstants` object in `app/src/main`. That is exactly wrong here — ad IDs are `buildConfigField` / `resValue` only. Say so in a comment where a reader would otherwise expect one.

**Google test IDs** (verified): rewarded `ca-app-pub-3940256099942544/5224354917`; interstitial `ca-app-pub-3940256099942544/1033173712`; app ID `ca-app-pub-3940256099942544~3347511713`. Google publishes no test Play Games project ID.

**Property/env key names (Claude's discretion, decided here):** `ADMOB_APP_ID`, `ADMOB_REWARDED_AD_UNIT_ID`, `ADMOB_INTERSTITIAL_AD_UNIT_ID`, `PGS_PROJECT_ID` — identical spellings for `local.properties` keys and CI environment variables.
