<objective>
The two pieces of device-local state cloud save introduces: a persisted "cloud push pending" marker
(D-01's retry, in the shape of Phase 12 D-10's dirty flag) and the last Play Games player id this
device's progress was merged with (D-12's account-switch gate).

Purpose: both must survive process death, and both must fail open in a direction that is argued
rather than assumed — a corrupt read of the player id must mean "merge silently", never "show the
dialog that can wipe the device".
Output: two new `open` DataStore accessor classes and two new keys on `PlayGamesPreferences`.

**Discretion resolved (CONTEXT "where the cloud push pending marker lives"):** a **sibling
`CloudSyncStore`**, not a second key on `SubmissionSyncStore`. `SubmissionSyncStore`'s own KDoc
argues that a flag with no atomicity relationship to the existing pair deserves its own accessor;
the cloud marker has none with `SUBMISSIONS_PENDING` — a pass can succeed at leaderboards and fail
at the snapshot, and those two outcomes must be independently recoverable. The **keys** still live
together in `PlayGamesPreferences`, per its existing "every `play_games_*` name in one object" rule.
Keys apart, accessors apart, exactly the established pattern.
</objective>

   sign-in) and a corrupt/IO read both read as `null`, and `null` means "merge silently per D-02",

   offer a player the option to wipe their own device. It must also state that the id stored here is
   `GamesSignInState.SignedIn.playerId` and that it is never logged (T-11-04).

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-04 | Tampering / Elevation | `CloudProfileStore.mergedPlayerId` fail-open direction | mitigate | An unreadable or absent stored id reads as `null`, and `null` is defined as "first-ever sign-in → merge silently" (D-12), never "show the destructive profile-swap dialog". A corrupt preferences file therefore cannot offer a player the wipe path. Acceptance criterion: the "fresh store emits null" behavior test plus the absence of any `DEFAULT_MERGED_PLAYER_ID` constant. (ASVS V4) |
| T-13-05 | Information Disclosure | player id at rest and in logs | mitigate | The player id is stored only in the app-private DataStore and is never logged: `grep -rn "Log\.\|println\|Timber"` over both new files returns 0 hits, extending the T-11-04 gate. (ASVS V7) |
| T-13-06 | Denial of Service | DataStore write failure during `setPushPending` | mitigate | Writes are `runCatching`-wrapped with `CancellationException` rethrown, so a full disk drops the marker rather than crashing an application-scoped coroutine. Acceptance criterion: the "write failure does not throw" behavior test. (ASVS V7) |
