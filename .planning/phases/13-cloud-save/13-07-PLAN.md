<objective>
CLOUD-03's two pieces of listing metadata: the one-line description and the cover image. Both live in
`platform/games/save/` because both need an Android `Context` and `data/` must stay Context-free.

Purpose: a saved game the player cannot recognise in the Play Games saves list is a saved game they
will distrust. The description is built from the Phase 12 SQL aggregates the app already computes,
and the cover is the app's own launcher art — rasterized from the existing vectors rather than
committed as a PNG, so there is exactly one copy of the art in the repo and it cannot silently drift.
Output: one drawable, two platform utilities, one string, two tests.

**Discretion resolved (cover PNG generation):** runtime rasterization at first use, cached for the
process, at 512 px — not a build-time PNG. The repo deliberately contains no PNG anywhere
(`res/mipmap-anydpi/ic_launcher.xml` says so in a comment) and has no rasterizer in its authoring
pipeline; a committed PNG would be an un-reviewable binary that diverges from the vectors.
</objective>

`res/drawable/cloud_save_cover.xml` — a `<layer-list>` with two items, `@drawable/ic_launcher_background`
then `@drawable/ic_launcher_foreground`, with an XML comment explaining why this file exists rather
than rasterizing `R.mipmap.ic_launcher`: on API 26+ that resolves to the `<adaptive-icon>`, whose
`AdaptiveIconDrawable.draw()` applies its own mask, so the cover would come out circle-cropped and
launcher-dependent. This composite is deliberately unmasked and full-bleed.

`CoverImageSource.kt` — `@Singleton class CoverImageSource @Inject constructor(@param:ApplicationContext
private val appContext: Context)` with `@Volatile private var cached: Bitmap? = null` and
`suspend fun coverOrNull(): Bitmap?` that returns the cache when present, otherwise hops to
`Dispatchers.Default` and, inside `runCatching`, resolves
`ContextCompat.getDrawable(appContext, R.drawable.cloud_save_cover)` and calls
`toBitmap(CloudSaveConstants.COVER_PX, CloudSaveConstants.COVER_PX, Bitmap.Config.ARGB_8888)` from
`androidx.core.graphics.drawable` (already on the graph via core-ktx 1.18.0). `.getOrNull()` the
result and cache it. It must **never** throw — a `null` cover means the commit omits
`setCoverImage` and still succeeds, which is the designed degradation.

KDoc must record: (a) that **no Activity is needed** — `@ApplicationContext` suffices, and only
`PlayGames.getSnapshotsClient` needs an Activity; (b) assumption A3 — vector inflation on
`Dispatchers.Default` relies on `Resources`' internal synchronization, and the failure mode is a
`null` cover, which is already the designed degradation; (c) assumption A1 — a 512x512 ARGB_8888
bitmap is 1 MB *in memory* but `setCoverImage` transports it PNG-compressed via `BitmapTeleporter`,
and this art (flat gradients plus 33 circles) compresses far below the 800 KB ceiling; if UAT test 12
ever measures it close, lower `COVER_PX`, which is one constant.

`CoverImageSourceTest.kt` — Robolectric, covering every `<behavior>` bullet. For the "not blank"
assertion, sample `getPixel` at the centre and at a corner and assert they differ. For the size
assertion, compress to a `ByteArrayOutputStream` and assert `size < 800 * 1024`, putting the measured
byte count in the assertion's failure message.
