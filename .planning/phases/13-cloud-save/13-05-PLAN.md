<objective>
The data layer's half of cloud save: turn stored rows into a `CloudProgress` (export), merge a remote
`CloudProgress` back into storage in one transaction (import), and give the D-14 replace path an
awaitable wipe.

Purpose: the repository is the single source of truth (ARCHITECTURE Anti-Pattern 2) — the cloud layer
must never touch a DAO. This plan is also where CLOUD-04 becomes structural rather than careful:
`importProgress` returns `ImportOutcome`, never `NewBests`, so the "New best!" flag and the Results
celebration are unreachable from an import by construction.
Output: five additive DAO members, an awaitable ladder merge, three repository members, and the
Robolectric test that pins all of it including two negative assertions.

**No Room schema change.** Every DAO member added here is an additive `@Query`/`@Upsert` over an
unchanged entity, so `DB_VERSION`, `Migrations.kt`, the exported schema JSON and `MigrationTest` are
all untouched. If the executor finds a schema change is genuinely needed, stop and run the full Room
bump ritual rather than editing an entity quietly.
</objective>

| decoded cloud payload → local database | Values have already been validated by `CloudProgressCodec.decode` (plan 13-04), but the merge-before-write here is the second control that stops a *well-formed but stale* remote row from destroying local progress. |
