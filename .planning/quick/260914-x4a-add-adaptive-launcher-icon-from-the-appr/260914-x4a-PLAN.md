<geometry_reference>

All four vectors use the SAME root attributes, so the design's 512-canvas numbers can be
copied verbatim:

```
android:width="108dp" android:height="108dp"
android:viewportWidth="512" android:viewportHeight="512"
```

108dp / 512 units → **1 viewport unit = 0.2109 dp**.

### Safe-zone scale (this is the one derived number — do not change it)

The adaptive canvas is 108dp; launchers guarantee only the centre **66dp circle**
(radius 33dp = `33 × 512 / 108` = **156.4 units**).

The cross slab spans x/y 44..468. Its outermost geometry is the eight outer corner arcs
(corner radius 20), whose arc centres sit at e.g. (196, 64) — distance from the board
centre (256, 256) is `sqrt(60² + 192²)` = 201.2, so the true circumradius is
**201.2 + 20 = 221.2 units**.

`156.4 / 226.6` (using the un-rounded 226.6 square-corner bound) → **scale = 0.69**.
At 0.69 the real extent is `221.2 × 0.69` = 152.6 units = 32.2dp radius = **64.4dp
diameter**, comfortably inside the 66dp safe circle. The board's bounding square becomes
`424 × 0.69` = 292.6 units ≈ 61.7dp, i.e. 0.57 of the 108dp canvas.

So every board element goes inside one group:

```xml
<group android:name="board" android:pivotX="256" android:pivotY="256"
       android:scaleX="0.69" android:scaleY="0.69">
```

### The 33 cells

7×7 grid, pitch 56. Cell centre `cx = 88 + 56*col`, `cy = 88 + 56*row`, col/row ∈ 0..6.
A cell is on the board when `row in 2..4 || col in 2..4`.

Row counts top to bottom: 3, 3, 7, 7, 7, 3, 3 = **33**.
Centre cell is `(col 3, row 3)` → **(256, 256)**, the only EMPTY cell.

Spot-check against the source HTML: `left:180; top:404` (40px dimple) → centre (200, 424)
= col 2, row 6. ✔

### Per-cell path recipes

Circle of radius `r` at `(x, y)`:
`M{x-r},{y} a{r},{r} 0 1,0 {2r},0 a{r},{r} 0 1,0 -{2r},0`

1. **Dimple** (all 32 occupied cells), radius 20 at `(cx, cy)`, fill `@color/ic_launcher_dimple_fill`.
   Drawn first; the peg sits 6 units higher so only the lower crescent shows — which is
   the lit part of the CSS inset shadow, hence the light tone. Flat fill is deliberate.
2. **Centre empty hole** at (256, 256), two paths:
   - radius 20, fill `@color/ic_launcher_hole_shadow`
   - radius 17 at (256, **259**), fill `@color/ic_launcher_hole_fill`
   The 3-unit downward offset of the inner disc leaves a shadow arc along the top —
   the vector stand-in for `inset 0 6px 9px`.
3. **Peg** (32 cells, centre cell excluded), radius 22 at `(px, py)` where `px = cx`,
   `py = cy - 6`. Fill is a radial gradient:
   `centerX = px - 6.6`, `centerY = py - 8.8`, `gradientRadius = 42`, stops
   `0 → ic_launcher_peg_highlight`, `0.55 → ic_launcher_peg_body`, `1 → ic_launcher_peg_rim`.
   (Derivation: CSS `circle at 35% 30%` in a 44px box → offset `(-6.6, -8.8)` from centre;
   default `farthest-corner` radius = `sqrt(28.6² + 30.8²)` ≈ 42.)
4. **Specular** (same 32 cells), ellipse rx 6 ry 4 centred at `(px - 6, py - 11)`,
   fill `@color/ic_launcher_peg_specular`:
   `M{px-12},{py-11} a6,4 0 1,0 12,0 a6,4 0 1,0 -12,0`

Example for col 2 / row 0 → cx 200, cy 88, px 200, py 82:
- dimple `M180,88 a20,20 0 1,0 40,0 a20,20 0 1,0 -40,0`
- peg `M178,82 a22,22 0 1,0 44,0 a22,22 0 1,0 -44,0`, gradient centre (193.4, 73.2)
- specular `M188,71 a6,4 0 1,0 12,0 a6,4 0 1,0 -12,0`

**Draw order inside the group:** slab → 32 dimples → centre-hole shadow → centre-hole
fill → then per peg: peg circle immediately followed by its specular.

**Path count for `ic_launcher_foreground.xml`: 1 + 32 + 2 + 32 + 32 = 99.**

### Background

- Gradient rect, full bleed: `M0,0 H512 V512 H0 Z`, linear gradient
  `startX=0 startY=0 endX=0 endY=512`, `ic_launcher_violet_light` → `ic_launcher_violet_deep`.
- Glow: circle radius 180 at (256, 236) (CSS `left:76; top:56; 360×360`), radial gradient
  `centerX=256 centerY=236 gradientRadius=180`, stops `0 → ic_launcher_glow`,
  `0.7 → ic_launcher_glow_fade`, `1 → ic_launcher_glow_fade`.
- Legacy background is the same two paths, except the gradient rect becomes a rounded
  rect with radius 92 (≈18% of 512) so the API 24–25 icon is not a raw square tile:
  `M92,0 H420 A92,92 0 0 1 512,92 V420 A92,92 0 0 1 420,512 H92 A92,92 0 0 1 0,420 V92 A92,92 0 0 1 92,0 Z`
  The rounding cannot clip the board: the corner regions are `x<92 && y<92` (and mirrors),
  while the slab's nearest approach to any corner is (176, 44) / (44, 176).

### Deliberate fidelity losses (record these in the SUMMARY)

- **No blurred drop shadows.** VectorDrawable has no blur primitive. The slab's
  `drop-shadow(0 18px 20px rgba(46,16,101,0.45))` and each peg's
  `0 6px 10px rgba(46,16,101,0.35)` are dropped. Launchers apply their own elevation
  shadow to the masked icon, and the peg's dark `#BE185D` gradient rim already reads as
  grounding. A hard-edged offset duplicate path — the only shadow a vector could draw —
  would look like a rendering bug at 48dp.
- **Specular ellipses are not rotated.** The CSS applies `rotate(-25deg)` to a 12×8px
  highlight; at final size that ellipse is ~1.7dp wide, where the rotation is invisible.
  Rotating it would cost 32 extra `<group>` wrappers.
- **Dimples are flat, not inset-shaded**, for the 32 occupied cells (only a crescent
  shows). The centre hole — the one cell the whole design is about — keeps its two-tone
  inset treatment.
- **Monochrome hole radius is 15, not 20** (centre hole stays 20). At 0.69 scale a
  20-unit hole leaves only 2.3dp of webbing between neighbours, which turns to mush under
  a single flat tint; 15 gives `56 - 30 = 26` units ≈ 3.8dp of webbing. The larger centre
  hole preserves the "one empty cell" read.

### Monochrome layer — chosen variant

**All 33 holes cut out**, not the centre-hole-only alternative. A cross with a single
dot does not read as a peg board; the perforated cross does, and at the radii above it
stays legible at 48dp. One `<path>` with `android:fillType="evenOdd"`: the slab path
above, concatenated with 32 radius-15 circle subpaths and one radius-20 circle at
(256, 256). Same `<group>` scale 0.69. Fill `@color/ic_launcher_mono_ink`.
