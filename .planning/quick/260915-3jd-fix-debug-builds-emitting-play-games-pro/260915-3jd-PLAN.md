<objective>
Debug APKs ship `com.google.android.gms.games.APP_ID` = "0", so Play Services looks up game 0
for `com.erman.pegsolitarie`, the backend answers NOT_FOUND, and the SDK returns
`isAuthenticated=false` with no error — which the Settings sign-in row renders as a silent
cancel. Root cause is already diagnosed on-device: `AdIdResolution.resolve(isRelease=false)`
returns `AdIdDefaults.TEST_GAMES_PROJECT_ID` unconditionally, because DEF-06-01 hard-wired the
*whole* debug branch and `PGS_PROJECT_ID` happens to live in `AdIdKeys.ALL`.

Purpose: make the debug branch carve out `PGS_PROJECT_ID` — honour a configured value
(env over local.properties), fall back to the placeholder only when unset — exactly as
`GamesIdResolution` already does for the 27 leaderboard/achievement IDs per D-17. The three
AdMob IDs stay hard-wired to Google's test units; DEF-06-01 is narrowed, not reversed.

Output: a one-line resolver change, the doc comments that explain the carve-out, and JVM tests
in `build-logic` that pin both halves of the rule.

Do NOT re-investigate the root cause. Do NOT touch `app/build.gradle.kts` — `debugIds.gamesProjectId`
already flows to `resValue("string", "game_services_project_id", ...)` at line 263.
</objective>
